> **生成日期：2026-10-05（今天生成）**
> 前置条件（除特别说明外通用）：后端服务已启动；`GET /api/v1/health` 返回正常；已配置至少一个已验证的视频 provider。

## 模块 A：视频生成接口（POST /api/v1/videos/generate）

| 用例编号 | 标题 | 优先级 | 类型 | 前置条件 | 步骤 | 预期结果 |
|---|---|---|---|---|---|---|
| VID-GEN-001 | t2v 文生视频正常生成 | P0 | 功能 | 任一支持 t2v 的 provider 已配置验证 | 1. POST `/videos/generate`，body：`{"prompt":"一只猫在草地上奔跑","mode":"t2v","duration":5,"resolution":"720p"}` 2. 记录返回 `task_id` | 返回 200，含 `task_id`、`status`；任务进入排队/运行态 |
| VID-GEN-002 | i2v 首帧图生视频 | P0 | 功能 | 生图或本地图 URL 可用 | 1. 准备一张 9:16 图片 URL 2. POST `/videos/generate`，`mode=i2v`，`first_frame_url=<url>` | 200，任务创建成功；最终视频首帧与输入图一致 |
| VID-GEN-003 | i2v 缺少首帧应报错 | P0 | 异常 | — | POST `/videos/generate`，`mode=i2v`，不传 `first_frame_url` | 4xx，错误信息明确指出缺少首帧 |
| VID-GEN-004 | r2v 参考视频/图生成 | P1 | 功能 | provider 支持 r2v（minimax_h3/seedance/kling/wan3） | POST `/videos/generate`，`mode=r2v`，传 `reference_images`（≤9 张）或 `reference_videos` | 200，任务创建成功 |
| VID-GEN-005 | 首帧+尾帧（关键帧插值） | P1 | 功能 | provider 支持尾帧（minimax_video 旧版等） | `mode=i2v`，同时传 `first_frame_url` 与 `last_frame_url` | 任务成功；成片从首帧平滑过渡到尾帧 |
| VID-GEN-006 | previz 视频自动提升为参考视频 | P2 | 功能 | — | `extra` 中传 `previz_video_url` | 该 URL 被自动归入 `reference_videos`，任务正常 |
| VID-GEN-007 | 时长边界：最短 3s | P1 | 边界 | — | `duration=3` | 接受；实际成片时长≈3s（provider 钳制规则内） |
| VID-GEN-008 | 时长边界：最长 15s | P1 | 边界 | — | `duration=15` | 接受（provider 支持范围内）；超出 provider 上限时被钳制或返回明确错误 |
| VID-GEN-009 | 时长非法值：0 / -5 / 16 / "abc" | P1 | 边界/异常 | — | 分别传入非法 duration | 4xx，参数校验错误信息清晰，不产生脏任务 |
| VID-GEN-010 | 分辨率参数：720p / 1080p | P0 | 功能 | provider 支持 1080p | 分别传两种分辨率 | 任务成功；`ffprobe` 验证成片实际分辨率一致 |
| VID-GEN-011 | provider 不支持的分辨率 | P1 | 异常 | 选择仅支持 768P/2K 的 minimax_h3 传 `resolution=1080p` | 提交生成 | 钳制到最近支持档位或返回明确不支持的错误（行为与文档一致） |
| VID-GEN-012 | 画幅比例 aspect_ratio 各值 | P1 | 边界 | — | 依次传 `9:16`、`16:9`、`1:1` | 成片实际画幅与请求一致 |
| VID-GEN-013 | seed 固定复现性 | P2 | 边界 | — | 相同 prompt+seed 连续生成两次 | 两次成片首帧视觉高度相似（同一模型下） |
| VID-GEN-014 | 显式指定 provider | P0 | 功能 | 多个 provider 已配置 | `provider="seedance"` 提交 | 任务由 seedance 处理（响应 `provider` 字段可验证） |
| VID-GEN-015 | 未指定 provider 自动选择 | P0 | 功能 | 仅一个 provider 已配置验证 | 不传 `provider` | 自动选中该已验证 provider；comfyui_video（本地占位）不参与自动选择 |
| VID-GEN-016 | 指定未配置的 provider | P1 | 异常 | — | `provider="nonexistent_provider"` | 4xx/明确错误，不崩溃 |
| VID-GEN-017 | provider 停用后禁止生成 | P1 | 异常 | 通过扩展体系停用某 provider | 提交生成请求 | 被 `ensure_provider_enabled` 拦截，返回明确停用提示 |
| VID-GEN-018 | 空 prompt / 超长 prompt | P1 | 边界 | — | `prompt=""`；`prompt`=超长文本（如 5000 字） | 空值被拒；超长文本被钳制或报错，不产生悬挂任务 |
| VID-GEN-019 | fps 与 extra 参数透传 | P2 | 功能 | — | `fps=24`，`extra={"steps":30,"cfg":7}` | 参数被平铺合并生效，任务正常 |
| VID-GEN-020 | 并发提交多个生成任务 | P1 | 性能 | — | 并发 POST 5 个生成请求 | 全部返回 task_id；状态轮询互不干扰；无任务丢失 |

## 模块 B：视频任务状态轮询（GET /api/v1/videos/status/{task_id}）

| 用例编号 | 标题 | 优先级 | 类型 | 步骤 | 预期结果 |

| VID-ST-006 | 任务落盘持久化后重启可查 | P1 | 异常 | 提交任务 → 重启后端 → 查询状态 | TaskCenter 落盘的任务在重启后仍可查询到状态 |
