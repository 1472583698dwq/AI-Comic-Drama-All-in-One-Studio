## 素材库（AssetLibrary.tsx）标签与搜索体验改造

用户反馈素材库界面标签难用（截图：标签"测试，试二，人人"被存成单个 pill 堆在一起）。本次改动：

1. **标签 chip 化 + 行内编辑**（client/src/components/asset/AssetLibrary.tsx）
   - 新增 `splitTagValue` / `normalizeTags` 工具函数：按中英文逗号/顿号/分号/换行拆分并去重（保序），修复历史脏数据把混排标签存成单字符串的问题；列表卡片与详情面板统一走归一化。
   - 详情面板标签区重写：每个标签独立 chip 平铺；点击 chip 行内编辑（Enter 提交 / Esc 取消 / 失焦提交 / 清空=移除）；hover 出 × 移除。
   - 保存走 `PUT /assets/{id}` 局部字段（FormData `tags`=JSON 数组 + `actor_project_id`），store `updateAsset` 会就地更新列表。
   - 写权限与后端 `writable_by` 同口径：全局素材仅出生项目可改，共享给我的只读（UI 禁用编辑入口）。
2. **快速添加已有标签**：`apiService.getAssetTags(q?, project_id?)` 接既有 `GET /assets/tags`；点「添加标签」出输入框 + 建议下拉（输入 200ms 防抖拉取，已持有的过滤，点选即加，Enter 连续添加）。
3. **搜索防抖**：停止输入 500ms 自动检索（`searchTimer` ref + effect，与 store `q` 一致时跳过）；Enter/「搜索」按钮立即触发并清挂起定时器。
4. **后端兼容**（server/app/api/asset_routes.py `_parse_json_list`）：逗号分隔增加中文逗号/顿号/分号替换，从源头避免"测试，试二，人人"式单标签。

验证：client `npx tsc -b` 零错误；`npm test` 674/674 通过；后端 `py_compile` 通过。未启动服务，UI 验证走 5173 由用户侧确认。

备注：AssetPickerModal 的搜索仍是每次输入即刷新（未加防抖），本次按显式范围未动，可作为后续项。

## 素材库标签 UI 三个 bug 修复（用户截图反馈，已对 live 数据取证）

用户反馈：① 标签区"变成三个标签连到一起"；② 删除一个标签后「添加标签」下拉什么都没有。对 127.0.0.1:8000 实测取证后定位：

1. **GlobalAiPolish 全局浮钮劫持标签输入框**：GlobalAiPolish.tsx 监听所有 input/textarea focus，在聚焦元素右上角弹「✨ AI 润色」 pill——点标签 chip 行内编辑或点「添加标签」时它贴在输入框上，与相邻 chip 视觉粘连，看着像三个 pill 连在一起。修复：focusin 增加 `data-no-polish` 退订（与 SelectionPolish 既有约定一致），两个标签输入框打上该属性（AssetLibrary.tsx）。
2. **建议下拉展示历史混排脏数据为单行**：`GET /assets/tags` 返回的是原始 tag 字符串，旧数据"测试，测试二，人人"（中文逗号未拆）在下拉里是一行。修复：前端对 pool 过 `normalizeTags` 拆回独立项。
3. **下拉删一个标签后就空**：旧实现把"已持有"的 tag 过滤掉；用户当前项目无带标签资产，项目口径 pool 恰好=已持有的 [测试,测试二] → 过滤后为空。修复：已持有的不过滤，仅行尾标注「已添加」（Check 图标+置灰）；pool 空/请求失败分别给提示行；pool 改全库口径（不再传 project_id，本地单机应用标签建议不做项目隔离）；effect deps 加 `selTags.join('\u0001')`，增删后下拉即时刷新。

验证：tsc -b 零错误、npm test 674/674。涉及文件：AssetLibrary.tsx、GlobalAiPolish.tsx（后端 asset_routes.py 中文逗号修复是上一轮的，仍在）。
