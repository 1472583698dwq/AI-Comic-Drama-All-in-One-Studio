## 一、扩展点体系

### 1.1 ❌ 组件级前端插件机制（任意 React 注入）
- **现状**：前端只有声明式 DSL（槽 block / 画布节点 spec / 主题变量），插件无法注入自定义组件与主题皮肤之外的 UI 结构。
- **影响**：复杂交互（自定义面板、可视化控件）只能等内置宿主或走声明式近似表达。
- **备选方案**：保持"代码在服务端"的安全模型不引入远程组件；或引入静态契约 + iframe/沙箱渲染的组件级扩展（成本高，需单独设计）。
- **建议**：暂不作为；若要做，先出设计文档（安全边界、加载协议、版本兼容）。

### 1.2 ❌ `canvas_nodes` 未接 Creator 造节点流
- **现状**：槽（storyboard_slot）有 Creator 提案→试跑→持久化链路（`agent/creator.py::_generate_slot_spec`），画布节点没有对应分支。
- **影响**："让导演造一个节点"做不到，只能从插件包安装。
- **验收**：`creator.propose_capability` 支持 `canvas_node` kind，生成 spec 草案 → 试跑（调用一次扩展）→ persist 落 `storage/canvas_nodes/`。
- **工作量**：中（约 0.5~1 天，参照 slot 分支）。

## 二、插件系统自身

### 2.1 ❌ `mcp_tools` 无沙箱
- **现状**：插件查壳工具在服务进程内执行，只靠 `STUDIO_TRUSTED_MODE` 总闸；provider code 模式 / custom_nodes 有受限沙箱。
- **影响**：开启 trusted 后插件代码拥有进程全部权限。
- **可选**：把 `run_plugin_tool` 改为与 `code_provider` 同款受限沙箱（网络用 `api.httpx`），或引入子进程隔离 + 资源上限。
- **工作量**：中。

### 2.2 ❌ 无签名/来源信任、无插件更新机制、依赖不自动安装
- **现状**：安装即信任；同 id 重复安装直接拒绝（需卸载重装）；`dependsOn` 只校验不自动装。
- **验收**：① 插件 zip 签名/Hash 白名单（可选）；② `POST /plugins/{id}/upgrade` 原子升级（保留数据）；③ 依赖缺失时给出可一键安装的提示。
- **工作量**：中。

### 2.3 ❌ 跨插件引用无运行时校验
- **现状**：槽/画布节点的 `run.extension`、exporter 的 `run.extension` 引用其他插件贡献时，只在执行时报"扩展不存在/未启用"，安装/启用期不校验。
- **验收**：插件 enable 时静态扫描其 JSON 中的 `run.extension`，不存在则 warning（不阻断）；或允许 manifest 声明 `requiresExtensions`。
- **工作量**：小~中。

### 2.4 🟡 扩展启停热刷新仍有缺口
- **现状**：主题/画布节点/导出器/导演包已热刷新；**分镜槽宿主**（`slots/loader.ts`）只随 `ShotInspector` 挂载/项目切换同步，没有监听刷新事件。
- **验收**：`slots/loader.ts` 增加 `storyboard-slots-refresh` 监听，扩展中心/插件中心在槽启停后派发。
- **工作量**：极小（~30 分钟）。

## 三、前端展示层

### 3.1 ❌ `PluginActionButton` 的 URL 结果不显示、不回写
- **现状**：`shot.actions` 按钮执行返回 `image_url/video_url/audio_url` 时静默成功；只有 `shot.tabs` 的按钮有 JSON 摘要 + 写回按钮（`WriteBackButtons`）。
- **验收**：抽出共用结果组件，动作按钮同样展示摘要并支持写回首帧/视频/配音。
- **工作量**：小（~1 小时）。

### 3.2 ❌ 分镜槽 block 种类少
- **现状**：只支持 `info / shot_field / buttons` 三种；无表格、富文本、条件显隐、图片预览等。
- **验收**：至少补 `image`（字段图预览）、`kv`（键值列表）、`when`（按字段条件显隐）。
- **工作量**：小~中。

### 3.3 ❌ 扩展中心无详情页
- **现状**：列表有 `detail_hint` 但不可点，看不到完整声明/依赖/贡献明细/最近执行。
- **验收**：点击条目打开详情抽屉：完整 JSON、依赖、执行统计（telemetry）、快速跳转宿主（生成源/工作流/槽管理）。
- **工作量**：小~中。

### 3.4 ❌ MCP 工具无独立调用/结果 UI
- **现状**：工具只能在 MCP 弹窗/Agent 对话里调用；插件工具没有 schema 表单。
- **验收**：MCP 工具面板按 `input_schema` 生成表单 → 调用 → 结构化结果预览；插件工具标注 trusted 闸。
- **工作量**：中。

## 四、Agent 与量产能力

### 4.1 ❌ 骨骼动画 / 表情 / 口型
- **现状**：导演台姿态为整体变换模拟（`applyPoseToGLB` 旋转/位移），无骨骼重定向、表情 morph、口型同步。
- **验收**：至少骨骼姿态重定向（Mixamo/CC0 rig 映射）+ 口型 viseme 驱动（按 TTS 时长/音素）。
- **工作量**：大（数天）。

### 4.2 ❌ 审片—重抽闭环
- **现状**：生成完成即结束，没有"评分→标记不满意→自动重抽/换源重抽"的闭环。
- **验收**：分镜/画布节点支持审片动作（评分/标签）→ 批量重抽队列 → 保留最佳候选。
- **工作量**：中~大。

### 4.3 ❌ 顶级云视频源
- **现状**：已接 MiniMax H3 / Seedance / Kling / Wan3，但未做质量对比与自动择优。
- **工作量**：中（每源参数/计费/失败策略对齐）。

### 4.4 ❌ 多集连发
- **现状**：一键成片是单次任务；无"多集批量提交 + 队列 + 统一回收"。
- **验收**：批量提交 N 集 → 任务中心统一看板 → 成片入库。
- **工作量**：中。

### 4.5 ❌ Agent v1→v2 迁移收尾
- **现状**：v2 事件溯源内核已可用，`AGENT_ENGINE` 仍可回退 v1（langchain_engine 保留）。
- **验收**：默认 v2、v1 标记 deprecated、文档单轨；清理 `.bak`。
- **工作量**：中（回归量大）。

### 4.6 ❌ `character_weight(s)` 各源消费验证
- **现状**：参考装配统一后字段已下发，但各 provider 是否真实消费未系统验证。
- **验收**：按源测试矩阵（image/video code/HTTP/ComfyUI）验证权重生效或明确标注不支持。
- **工作量**：小~中（依赖真实 Key）。
