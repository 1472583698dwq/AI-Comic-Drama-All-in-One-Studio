# 自定义源（ProviderDefinition）参数与输入暴露标准 v1

> **归属**：AI 漫剧 Studio · 无限画布 + 分镜工作台共用  
> **版本**：v1.0 2026-09-02  
> **关联代码**：`server/app/models/provider_definition.py:62` `server/app/api/provider_routes.py:439` `server/app/providers/generic/code_provider.py:285` `client/src/components/canvas/controls/DynamicControl.tsx:1` `client/src/components/canvas/NodeAgentConsole.tsx:15` `client/src/components/canvas/providerSkills.ts:40` `client/src/components/canvas/nodeRegistry.ts:1` `client/src/components/storyboard/ShotInspector.tsx:1` `client/src/components/ui/ProviderPicker.tsx:1`
> **目标**：彻底解决“提示词外参数该摆哪、怎么渲、谁来填”——所有非 `prompt/text` 的能力以声明式 Schema 驱动，在画布与分镜两端一致暴露，并明确 Agent/用户分工。

## 一、问题诊断

| 现象 | 代码证据 | 后果 |
|---|---|---|
| `params_schema` 扁平无分组 | `provider_routes.py:439 _default_params_schema` 4参直接平铺，前端 `NodeAgentConsole:15 paramsSchemaToSpecs` 无分组直接 `map` | 画布高级参数与基础参数混排，用户找不到 `resolution`，Agent 也不知该动哪项 |
| 输入与参数混淆 | `http_provider.py:317` `context` 把 `aspect_ratio/resolution` 与 `reference_images` 同层合并，`code_provider.py:285 merge_user_params` 才做 `dynamic_inputs>extra` 双通道 | `fps` 等视频参数曾误打到 Comfy 工作流非暴露口 `ShotInspector:367` 抛 `未定义的参数` |
| 枚举漂移 | 模板写死 `480p/720p` 但真实 API 要 `480p竖`，`provider_routes.py:270 _extract_params_schema_from_code` 靠尾注释 `# PARAMS_SCHEMA` 补 | 用户选 `720p` 被校验拦截 `code_provider.py:302 validate_user_params` |
| 暴露面不统一 | 画布 `providerSkills:40 extractSlotsFromProvider` 读 `input_schema.x-handle`，分镜 `ShotInspector:367` 却用 `workflowExposedInputs` + `providerParams` 分箱轮询 | 同一自定义源在画布有垫图槽、在分镜没有；或反之 |
| Agent 边界模糊 | `NodeAgentConsole:202 handleExecute` 把 `customParams` 全量当 `paramsOverride` 发，`langchain_engine` 也不知哪些可代填 | 关键 `seed/api_key` 被 Agent 随意改，或用户明明想让 Agent 定 `steps` 却得手填 |

## 二、设计原则

1. **三层分离**：`输入(input_schema)` 决定“连什么”；`参数(params_schema)` 决定“怎么生”；`提示词(prompt/text)` 是两者的粘合剂。绝不交叉。
2. **声明式即 UI**：前端不硬编码任何 `aspect_ratio/resolution/steps` 名称，全部由 `params_schema.properties[].x-*` 驱动 `DynamicControl:22`。新增 API 只改 Schema，不改组件。
3. **单点解析**：`resolve_params_schema()` `server/app/api/provider_routes.py:289` 为唯一入口（显式 > 代码尾注释 > kind 默认），所有读取走它，杜绝枚举漂移。
4. **两端同源**：画布与分镜共用同一套 `input_schema → 插槽` / `params_schema → 控件` 解析，不再各自维护白名单。
5. **人机分工显式化**：每个字段用 `x-agent` 声明 Agent 可否代填，UI 用徽标与禁用态告知用户。

## 三、Schema 扩展规范

### 3.1 `input_schema` — “要喂什么数据”

驱动：画布插槽芯片、节点 Handle、分镜垫图拖拽。

```json
{
  "type": "object",
  "properties": {
    "prompt":           { "type": "string", "description": "画面提示词", "x-handle": "text",  "x-role": "prompt", "x-required": true },
    "negative_prompt":  { "type": "string", "description": "负向提示词", "x-handle": "text",  "x-role": "prompt_aux" },
    "first_frame":      { "type": "string", "format": "uri", "description": "首帧", "x-handle": "image", "x-slot": "first_frame", "maxItems": 1 },
    "last_frame":       { "type": "string", "format": "uri", "description": "尾帧", "x-handle": "image", "x-slot": "last_frame",  "maxItems": 1 },
    "reference_images": { "type": "array", "items": {"type":"string","format":"uri"}, "description":"角色/场景参考", "x-handle":"image", "x-slot":"reference_images", "minItems":0, "maxItems":4 },
    "ref_audio":        { "type": "string", "format":"uri", "description":"参考音频", "x-handle":"audio", "x-slot":"ref_audio" },
    "reference_video":  { "type": "string", "format":"uri","description":"参考视频(动作)", "x-handle":"video", "x-slot":"reference_video" }
  },
  "required": ["prompt"]
}
```

| 字段 | 含义 | 约定 |
|---|---|---|
| `x-handle` | 句柄类型 `text/image/audio/video` | 复用 `providerSkills:99` 识别，未声明 `format:uri` 的忽略 |
| `x-slot` | 归一化插槽键 `first_frame/last_frame/reference_images/ref_audio/reference_video` | 前端 `extractSlotsFromProvider:67` 以此去重 |
| `maxItems/minItems` | 数量约束 | 缺省 `image:1-4` `audio:1-1`，UI 据此限制多选与截断提示 `NodeAgentConsole:124` |

**禁止**：在 `input_schema` 放 `steps/resolution/duration` 等可量化参数，它们属于 `params_schema`。

### 3.2 `params_schema` — “怎么生”

驱动：`DynamicControl` + 画布高级面板 + 分镜 ProviderParamForm + Agent `paramsOverride`。

每个 `properties[k]` 标准 JSON Schema 基础上扩展 4 个 `x-*`：

```json
{
  "aspect_ratio": {
    "type": "string", "title": "画面比例", "description": "输出画面比例",
    "enum": ["9:16","16:9","1:1"], "default": "9:16",
    "x-category": "layout",      // 分组
    "x-visibility": "basic",     // 暴露级别
    "x-agent": "auto",           // 人机分工
    "x-priority": 10             // 组内排序
  },
  "steps": {
    "type": "integer", "title": "采样步数", "default": 20, "minimum": 4, "maximum": 60,
    "x-category": "quality", "x-visibility": "advanced", "x-agent": "suggest", "x-priority": 30
  }
}
```

| 扩展 | 取值 | 语义 | UI/执行影响 |
|---|---|---|---|
| `x-category` | `layout/motion/quality/audio/advanced` | 分组标签 | 画布按组折叠；分镜按 `visual/motion/dialogue` Tab 过滤 `layout+quality→visual, motion→motion, audio→dialogue` |
| `x-visibility` | `basic/advanced/hidden` | 暴露级别 | `basic` 默认展开；`advanced` 收进“高级参数”抽屉 `NodeAgentConsole:334`；`hidden` 仅代码可见不渲染（内部 `workflow_id` 等） |
| `x-agent` | `auto/suggest/manual` | 人机分工 | 见第五章矩阵；`auto` 项 Agent 可直接覆盖，`manual` 项 Agent 绝不碰 |
| `x-priority` | `0-100` 小者靠前 | 排序 | 组内按此排序，保证 `aspect_ratio` 永远在 `resolution` 前 |
| `x-control`（可选） | `slider/select/toggle/input` | 强制控件 | 缺省按 `type+enum` 自动推断 `DynamicControl:20`，仅特殊时覆盖 |

**默认枚举兜底**（`_default_params_schema`）：

| kind | basic | advanced |
|---|---|---|
| `image` | `aspect_ratio[9:16/16:9/1:1] resolution[480p/720p/1080p]` | `steps[4-60] cfg[1-15] seed` |
| `video` | `aspect_ratio resolution duration[3-15] fps[16/24/30]` | `steps cfg motion_strength seed` |
| `audio` | `voice_id emotion` | `speed[0.5-2] pitch[-12-12] volume[0-2]` |

真实 API 枚举与此不一致时，**必须**在代码尾追加一行合法 JSON 注释（`provider_routes.py:270` 自动解析，优先级高于默认）：

```python
# PARAMS_SCHEMA: {"type":"object","properties":{"resolution":{"type":"string","title":"分辨率","enum":["480p竖","720p竖","1080p竖"],"default":"720p竖","x-category":"layout","x-visibility":"basic","x-agent":"auto"}}}
```

### 3.3 `output_schema`

保持极简，仅声明产出句柄供画布连线校验 `nodeRegistry:39`：

```json
{ "image": { "image_url": {"type":"string","format":"uri","x-handle":"image"} },
  "video": { "video_url": {"type":"string","format":"uri","x-handle":"video"} },
  "audio": { "audio_url": {"type":"string","format":"uri","x-handle":"audio"} } }
```

## 四、两端暴露规则

### 4.1 无限画布 · 节点内 Agent 控制台 `NodeAgentConsole.tsx:42`

```
┌─ 标题栏：[生图Agent #a1b2] [skill pills]      [生成源下拉 ▼] [刷新] [高级⚙]
├─ 源能力摘要：该源支持 首帧×1 尾帧×1 参考图0-4  (describeProviderSlots)
├─ 插槽区：     [首帧 ⊕/缩略×] [尾帧] [参考图 ×3/4]  ← input_schema 驱动，required 红星，超限截断提示
├─ 高级参数区（抽屉）：按 x-category 分组，basic 常显，advanced 折叠 ← params_schema + DynamicControl
├─ 想法输入：   textarea（人话） ← 映射到 prompt/text
├─ Agent白盒：  skill/provider/model/params/reasoning ← _last_agent_plan
└─ 执行栏：     [就绪·源名]  [让Agent执行] ← buildSlotsPayload()+paramsOverride→ canvasAgentGenerate
```

* **提示词外参数**：一律进“高级参数区”，`basic` 默认可见，`advanced` 需点 ⚙ 展开。`hidden` 不渲染但随 `paramsOverride` 透传。
* **输入数据**：一律为插槽芯片；点击芯片弹 `CanvasResourcePickerModal:86` 四 Tab（画布产出/角色库/场景库/本地上传）。连线 `CreativeCanvas:182 handleNodeUpdate` 自动回填 `first_frame/reference_images` 并同步 `providerSkills:90 validate_user_params`。
* **Provider 切换**：`selectProvider:81` 保留 `params_schema.default` + `default_params` 合并，并按新源 `maxCount` 裁剪已挂载数组。

### 4.2 分镜工作台 · 三 Tab 检查器 `ShotInspector.tsx:70`

| Tab | 绑定源 | 输入区 | 参数区 |
|---|---|---|---|
| `dialogue` 台词 | `audioProvider` | `dialogue/text` + `ref_audio` 插槽（角色 VoiceID 自动注入） | `ProviderParamForm` 渲染 `x-category:audio` 的 `basic+advanced` |
| `visual` 画面 | `imageProvider` | `image_prompt` + `reference_images` 拖拽/角色立绘注入 `handleInjectCurrentCharacter:357` | 渲染 `layout+quality` 基本 + 高级 |
| `motion` 动态 | `videoProvider` | `video_prompt` + `first_frame/last_frame/reference_images`（首帧优先 `image_url`） | 渲染 `layout+motion` 基本 + 高级 |

* **提示词外参数**：每个 Tab 内“源选择器”下方即 `ProviderParamForm`（复用 `DynamicControl`），不再与 `workflowExposedInputs:214` 混排。工作流模式时 `exposed_inputs` 的媒体型仍进插槽，数值型进 `params_schema` 合并去重，校验仍走 `validate_user_params` 单点。
* **批量**：`handleBatchAllImages:545` 等批量循环沿用同 Schema 组装 `dynamic_inputs`，失败项仅标 `error` 不阻断队列。

## 五、Agent 代填 vs 用户手填 矩阵

> 判定键为 `params_schema.properties[k].x-agent`，缺省：`layout→auto` `motion→auto` `quality→suggest` `seed/api_key→manual`

| 类别 | 字段举例 | Agent 行为 | 用户 手填 | 冲突解决 |
|---|---|---|---|---|
| **版式布局** `layout` | `aspect_ratio` `resolution` | `auto`：从 `project.aspect_ratio` 或分镜 `duration` 自动推断，首选写入；用户改后 Agent 不再覆盖 | 比例/分辨率下拉一键覆盖 | 用户显式值 > Agent 推断（`merge_user_params:285 dynamic_inputs > extra`） |
| **时长运动** `motion` | `duration` `fps` `motion_strength` | `auto`：`duration` 取 `shot.duration` 四舍五入，`fps` 取 24 默认；首尾帧齐时自动 `i2v` | 滑杆微调 | 同上，批量时尊重单镜覆写 |
| **画质采样** `quality` | `steps` `cfg` `sampler` `seed` | `suggest`：润色 `prompt` 时附带推荐 `steps:28 cfg:7`，仅在 `paramsOverride` 缺省时注入；`seed=-1` 时随机 | 高级抽屉手调，`seed` 锁定需 `manual` | Agent 仅填空，不抢占用户已填值 |
| **音频音色** `audio` | `voice_id` `emotion` `speed` | `auto`：绑定角色 `character.voice_id` 自动注入；`emotion` 由台词语义推断 `angry/whisper` | 下拉试听后锁定 | 角色绑定优先于 Agent 推断 |
| **输入插槽** `input` | `first_frame` `reference_images` `ref_audio` | `auto`：沿画布边拓扑收集 `collect_upstream_data:46` 或从资产库按 `visual_prompt` 召回 | 点击芯片手选/拖拽/本地上传 | 用户手选追加到 Agent 收集结果并去重 |
| **敏感/随机** | `seed(锁定)` `api_key` `workflow_id` | `manual`：永不代填 | 仅用户 | 校验层直接放行 `hidden` 项 |

**执行链路**：
1. 前端 `NodeAgentConsole:202 buildSlotsPayload + customParams → paramsOverride` 仅打包用户显式值。
2. 后端 `code_provider.py:302 validate_user_params` 只校验 `user_params` 显式集合，框架默认值不参与校验（避免误报）。
3. `ctx` 组装 `code_provider.py:599 GenericCodeImageProvider` 为 `user > req显式 > kind默认` 三级兜底。
4. Agent `canvasAgentGenerate` 的 `plan.params` 仅对 `x-agent:auto/suggest` 且前端未填的键做补全。

## 六、完整示例

### 6.1 生图自定义源（硅基 FLUX，真实枚举竖屏）

```json
{
  "id": "prov_flux_pro",
  "name": "硅基 FLUX Pro",
  "kind": "image",
  "language": "python",
  "code": "async def generate(ctx, api):\n    ...\n# PARAMS_SCHEMA: {\"type\":\"object\",\"properties\":{\"resolution\":{\"type\":\"string\",\"title\":\"分辨率\",\"enum\":[\"480p竖\",\"720p竖\",\"1080p竖\"],\"default\":\"720p竖\",\"x-category\":\"layout\",\"x-visibility\":\"basic\",\"x-agent\":\"auto\",\"x-priority\":20},\"steps\":{\"type\":\"integer\",\"title\":\"采样步数\",\"default\":28,\"minimum\":8,\"maximum\":50,\"x-category\":\"quality\",\"x-visibility\":\"advanced\",\"x-agent\":\"suggest\",\"x-priority\":30},\"cfg\":{\"type\":\"number\",\"title\":\"CFG\",\"default\":7,\"minimum\":1,\"maximum\":12,\"x-category\":\"quality\",\"x-visibility\":\"advanced\",\"x-agent\":\"suggest\"}}}",
  "input_schema": {
    "type":"object",
    "properties": {
      "prompt": {"type":"string","description":"画面提示词","x-handle":"text","x-role":"prompt"},
      "negative_prompt": {"type":"string","description":"负向提示词","x-handle":"text","x-role":"prompt_aux"},
      "reference_images": {"type":"array","items":{"type":"string","format":"uri"},"description":"参考图","x-handle":"image","x-slot":"reference_images","maxItems":2}
    },
    "required":["prompt"]
  },
  "params_schema": {
    "type":"object",
    "properties": {
      "aspect_ratio": {"type":"string","title":"画面比例","enum":["9:16","16:9","1:1"],"default":"9:16","x-category":"layout","x-visibility":"basic","x-agent":"auto","x-priority":10},
      "resolution": {"type":"string","title":"分辨率","enum":["480p竖","720p竖","1080p竖"],"default":"720p竖","x-category":"layout","x-visibility":"basic","x-agent":"auto","x-priority":20},
```

### 6.2 视频自定义源（MiniMax H3）

`input_schema` 含 `first_frame + reference_images[0-4]`，`params_schema` 含 `duration/fps/resolution + motion_strength(hidden)`。分镜 `motion` Tab 自动出现首帧预览与多参考图拖拽区，Agent 将分镜 `image_url` 自动喂 `first_frame`。
