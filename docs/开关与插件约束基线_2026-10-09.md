# 开关与插件约束基线（2026-10-09）

> 状态：**基线快照**（基于真实代码只读审计，证据行号截至 2026-10-09）
> 用途：《[前端 UI 开关热插拔设计](plans/2026-10-09-UI开关热插拔设计.md)》的约束依赖底座——该方案声明「不新增后端契约、不改开关语义」，本文档列出它依赖的既有约束与代码证据。基线之外的**缺口**不在此处，见设计文档 §2.5。

## 1. 开关体系：四类，无第五种

### 1.1 页面开关（page）

- 真相源：扩展覆盖层 `storage/extensions/state.json`，id 形如 `page:<pid>`（`server/app/core/pages.py:93-95`）。
- 定义清单 `PAGE_DEFS` 11 页（`pages.py:28-88`）；`config` `locked=True`（`pages.py:84-87`），停用入口被 registry 拦截（`server/app/extensions/registry.py:290-294`）。
- 未知 id：`is_enabled` 一律 False、不兜底放行（`pages.py:135-140`）。
- 路由守卫 `require` / `require_any`：关闭或未知 → 404（`pages.py:172-202`）。
- 首次播种幂等：顶层标记 `pages_seeded`（`pages.py:109-132`）。
- **路由挂载点**（关掉即 404 的接口族）：
  - `storyboard_slot_routes.py:18`（studio）
  - `timeline_routes.py:35`（canvas|timeline **共用**，`require_any`）
  - `onekey_routes.py:23`（studio|onekey **共用**，`require_any`）
  - `director_pack_routes.py:12`（director3d）
  - `canvas_routes.py:14` / `canvas_node_routes.py:18` / `custom_node_routes.py:17`（均 canvas）

### 1.2 功能开关（feature）

- 真相源：`storage/features.json`，扁平 `{id: bool}`；原子写 `.tmp` + `os.replace`（`server/app/core/features.py:115-124`）；读带 mtime/size 缓存，外部改文件即时生效（`features.py:76-112`）。
- 定义 `FEATURE_DEFS` 三项：`agent_multimodal` / `agent_subagent` / `agent_teams`（`features.py:38-55`），出厂默认全关。
- 未知 id：读一律 False（`features.py:133-138`）；写 `ValueError` **整批拒绝、不写坏文件**（`features.py:176-208`）。
- id 即契约：不可改名、不可复用，下线就保留定义置 default=False（模块 docstring，`features.py:19-20`）。
- 挂载点：`routes.py:2503`（/agent/upload）、`agent_team_routes.py:23`、`agent/tools/registry.py:244`、`agent/runtime/subagent.py:39`、`agent/runtime/attachments.py:31`。

### 1.3 UI 偏好（prefs）

- 真相源：本机 localStorage `ai_manju_ui_switches`（`client/src/stores/useUiPrefsStore.ts:15`）。
- 定义 `UI_SWITCH_DEFS`（当前 1 项 `sidebar_chat_history`，`useUiPrefsStore.ts:30-37`）；未知 id 不接收、避免写脏键（`:61-69`）；缺项/损坏回落出厂默认（`:41-56`）。
- 纯呈现：不进后端契约、不影响接口准入、不影响其他机器。
- 注：页面版本单选偏好（`page_variant.*`，字符串值）规划为 prefs 层的新子类，见设计文档 §2.4.1。

### 1.4 插件启停（plugin）

- 真相源：`storage/extensions/state.json` + 插件目录 3s mtime watcher 热重载（`server/app/plugins/manager.py:1106-1143`）。
- 生命周期端点：`POST /plugins/{id}/enable|disable|reload`、install / uninstall（`server/app/api/plugin_routes.py`）。
- 与前三类的关系：插件贡献**继承宿主层开关**，有效可见性 = 四类与运算（见设计文档 §2.3.1 有效可见性公式）。

### 1.5 部署级环境变量闸（不属于 UI 开关体系，仅记录）

- `STUDIO_TRUSTED_MODE`（`server/app/core/config.py:302, 338-347`，默认 "0"）。
- `STUDIO_PLUGIN_WATCH`（`manager.py:1112`，插件热重载 watcher 总闸）。

## 2. 后端插件生命周期约束

### 2.1 精确回滚（完整）

- enable 落盘追踪 11 类产物：provider_ids / skill_names / workflow_ids / mcp_tools / custom_nodes / canvas_nodes / theme_ids / exporter_ids / director_pack_ids / agent_profile_ids / agent_team_ids / installed_files（`manager.py:865-871`；模型 `server/app/plugins/models.py:55-67`）。
- disable 逐项回滚：
  - providers 反注册+删定义（`manager.py:893-909`）、workflows+同步 provider（`:915-924`）、mcp_tools 查壳反注册（`:929-933`）、custom_nodes（`:937-948`）、canvas_nodes（`:954-959`）、themes / exporters / director_packs（`:965-990`）、agent_profiles / agent_teams（`:996-1007`）、仅删追踪到的落盘文件（`:1011-1018`）、skills 目录树 `skills/.plugins/<pid>` 整树删除（`:1021-1030`）、追踪记录清零（`:1036`）。
- 幂等：disable 未启用 →「本就未启用」（`:884-886`）；enable 已启用 → 不重复（`:563-564`）；uninstall 先 disable（`:1041-1046`）；reload 对未启用插件仅重扫（`:1058-1069`）。
- 全生命周期持 RLock 串行（`manager.py:39-40`）。

### 2.2 id 与 manifest 校验

- manifest id 格式：`_ID_RE` 小写字母数字中划线（`manager.py:30, 230-231`）；`PluginManifest` `extra="forbid"`，未知字段拒绝（`server/app/plugins/models.py:34`）。
- 重复安装同 id：安装即拒，HTTP 400（`manager.py:321-322` + `plugin_routes.py:37-40`）。
- `extensionPoints` glob：仅路径围栏校验（禁 `..` / 绝对路径 / 盘符，`manager.py:165-172, 234-238`）。
- 扩展 id 命名空间 `kind:local_id`，插件来源 `kind:publisher/local_id`（`server/app/extensions/models.py:85-94`）——插件 id 天然不撞内置扩展 id。
- MCP 工具名带 `plugin_<pid>_` 前缀，冲突跳过（`manager.py:438-441`）。

### 2.3 trusted 闸（三类代码执行全覆盖）

- 闸门实现：`_trusted_gate_or_raise`（`server/app/mcp/server.py:27-35`）+ `is_trusted_mode_enabled`（`config.py:338-347`）。
- mcp_tools（插件查壳）：**强制过闸**（`manager.py:475-486`；统一执行口 `server/app/extensions/registry.py:163-165`；测试 `server/tests/test_extensions.py:263-285`）。
- custom_nodes：默认受限沙箱；`trusted=true` ∧ 总闸**双开**才出沙箱（`server/app/custom_nodes/manager.py:144-151`）。
- providers（code 模式）：同双开制（`server/app/models/provider_definition.py:110-112`）。
- overlay 停用闸**独立于** trusted：执行口统一 `guard.ensure_enabled`（`server/app/extensions/guard.py:61-68`、`manager.py:484-485`、`custom_nodes/manager.py:135-136`）。

## 3. 前端消费侧既有防护

### 3.1 开关 store

- `usePageStore`（`client/src/stores/usePageStore.ts`）：未知/关闭页 `resolveTab` 回落第一个可用页（`:215-222`）；未加载一律 false（`:201`）；加载失败 **fail-open** 启用 `FALLBACK_PAGES` 全默认页（`:63-75, 161-171`）——有意设计，准入兜底靠后端 404；不写 localStorage（`:15`）；`normalizeItems` 过滤非法项（`:94-109`）。

## 4. 基线声明（设计方案的依赖边界）

1. **四类开关的真相源与语义不在《UI 开关热插拔设计》改动范围**（page / feature / prefs / plugin，见本文 §1）。
2. **locked 语义**：后端仅 `config` 一处；前端 `locked` 是纯渲染语义，不新增后端字段（设计文档 §5.4-1）。
3. **精确回滚 ↔ 按 source 回滚的对称性**是 Phase 3/4 的前提：后端 `manager.py` 的产物追踪机制与前端注册表 `source` 批量反注册一一对应。
4. **已知缺口**（基线之外不存在或不完整的防护）不在本文档展开，统一见设计文档 §2.5；其中标注「仅记录」的项不属于该方案范围。
