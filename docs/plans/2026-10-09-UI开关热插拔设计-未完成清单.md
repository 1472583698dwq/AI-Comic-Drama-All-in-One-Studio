## 四、§3 契约与运行时规则的落地差

### 5. ⚠️ **`UISlot` 没有「无条目 / 开关未加载」的统一 fallback**

| 项 | 内容 |
|---|---|
| 出处 | §3.3「开关 store 未加载完 → 宿主渲染加载占位」（补充分支）；§9.2 精简项「加载占位收敛为 `UISlot` 的统一 fallback」 |
| 现状 | `UISlot` 在 `entries.length === 0` 时返回 `null`；「未加载 → 占位」是 **App 的分支**在做（渲染 `shell.loading` 条目）。槽位本身没有 `fallback` 能力，所以**其它宿主**（`settings.panels` / `sidebar.blocks` / `app`）在无条目时是静默空白 |
| 缺什么 | `UISlot` 增加 `fallback?: React.ReactNode`（以及「未加载」判定的统一口径），把加载占位从 App 收进槽里 |
| 影响 | 目前不影响正确性（页面槽由 App 兜底），但「统一 fallback」这条设计承诺未兑现 |
| ✅ 处理（2026-10-09） | `UISlot` 增加 `fallback?: React.ReactNode`；「未加载」判定统一进 `useResolvedSlot().loading`（页面槽看 pages 开关；其它槽只看**槽内条目实际依赖**的 feature store，prefs 本地同步读永不 loading）。语义分工：`loading` → **内置加载占位**（复用 `shell.loading` 锁定条目，不新增组件，且**不被宿主的 `fallback` 覆盖** —— 「还没拉到」与「就是没开」不是一回事，否则传了空态兜底的槽会在加载期闪一下全关空态）；已加载但无条目 → `fallback`。App 侧删掉 `!pagesLoaded` 分支，改传 `fallback={<UISlot host="shell.empty"/>}` |

### 25. 🔶 **feature 默认值口径（2026-10-10 已定稿：白名单制）**

产品口径：**新实例开箱要能走通一条完整视频链路**（画布 / AI 导演 → 分镜台 / 成片工作室 → 多轨剪辑 → 导出）。据此把 feature 契约由「出厂全关」升级为**显式白名单**：

- 默认**开**：`agent_multimodal`、`agent_subagent`（链路必需：看图 / 产物回投 + 一键成片依赖的子代理集群）；
