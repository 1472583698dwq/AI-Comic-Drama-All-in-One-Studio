# 接力文档 — 分镜工作台动态生成源单源化收口（去固定模板）

> **日期**：2026-09-02 · **范围**：分镜工作台（ShotInspector）生成源参数渲染与提交链路
> **触发问题**：分镜里选了工作流生成源后，界面仍按一套固定模板出参数，没有按该源真实的参数列表渲染；且填的值提交后被静默丢弃。

---

## 一、根因（四层叠加，缺一都修不好）

| # | 断点 | 位置 | 说明 |
|---|---|---|---|
| 1 | `params_schema` 有白名单与假回落 | `providers/workflow/manager.py::_build_provider_schemas_from_workflow` | 只收 `number/combo/boolean`，**4 个 text 暴露项被整体丢弃**；清单为空时硬塞 `{seed, steps:20, cfg:7.0}` 假参数 |
| 2 | `input_schema` 是写死的 | 同上 | image 恒为 `{prompt, reference_images}`、video 恒为四键，完全不看工作流实际暴露了什么 |
| 3 | 命名空间断裂 | 后端 vs `ShotInspector.tsx` | 暴露项 id 是 `num_30:3_steps`/`combo_49_aspect_ratio`，而 `params_schema` 的 key 是 `steps`/`49_aspect_ratio`。分镜提交处用 `exposedKeys.has(k)` 过滤源参数 → **交集为空，源参数全量丢失** |
| 4 | 丢中文标签 | 同上 + `providerSkills.ts` | prop 只写 `description` 不写 `title`，而前端取 `def.title \|\| key` → 界面显示 `49_aspect_ratio`、`30:16_sampling_mode.top_k`；存量 `x-visibility` 为空 → 31 项全挤在"高级"且无排序 |

另发现两处同源问题一并修掉：

- **ComfyUI 离线时清单塌陷**：`auto_detect_exposed_inputs` 依赖 `/object_info`，离线探测从 33 项退化成 4 项且 combo→text。启动同步会拿退化结果覆盖已存清单 → 生成源参数"莫名变少/下拉变手填"。
- **`txt_<节点>_<参数>` 注入丢失**：`_apply_dynamic_inputs` 对 `txt_` 前缀直接把 rest 当节点 id，`txt_30:27_string_b` 解析成节点 `30:27_string_b` → 不存在 → 静默 continue，该槽位永远写不进去。

## 二、改了什么

**后端**

- `_build_provider_schemas_from_workflow` 重写：`params_schema` 逐条来自暴露清单（含 text），**key 一律用暴露项原生 id**，值可被 `_apply_dynamic_inputs` 直接落节点，零标准名改写；补 `title`（真实中文名）与 `x-category/x-visibility/x-agent/x-priority`，命中标名的额外带 `x-std-key`；删除假回落。
- `input_schema` 仍保留标准句柄（`prompt/reference_images/first_frame/last_frame`）供画布连线与节点 Agent 自动装配，但 **prompt 的展示名取自工作流真实文本入口**并带 `x-comfy-id`，前端不再显示写死的"正向生图提示词"。
- 新增 `resolve_exposed_inputs(clean_wf, meta)`：`inspect_workflow_nodes` 与生成源 schema **共用同一份解析**，"参数与暴露"面板保存后生成源同步生效；并在离线退化时保留已存的 combo/number 类型与 id。
- 新增 `_persist_exposed_baseline` + `sync_workflow_provider` 的"绝不降级"取舍：已存清单更完整且工作流 hash 未变时，以完整清单为基线重建并固化进 `meta.exposed_inputs`；同步跳过条件扩展到比较 `params_schema/input_schema`，使 schema 规则升级后**存量源自动重建**。
- `pick_prompt_text_slot` 抽为单点规则，`init_providers` 两处重复的提示词猜测逻辑改为调用它（用户已显式填该槽时不覆盖）。
- `_apply_dynamic_inputs` 修 `txt_/img_/aud_/vid_` 带参数后缀的解析。
- `_enrich_params_schema` 给 `emotion/voice_id` 补 `x-role`，供前端判断该控件是否已由源自己提供。

**前端 `ShotInspector.tsx`**

- 生图 Tab 删除：独立的「ComfyUI 工作流」下拉、⭐️工作流暴露输入项块、写死的「正向生图提示词」区。参数区只剩两样 — 源声明的**输入区**（prompt + 插槽）与 `ProviderParamForm`（源参数全量）。
- 新增模块级 `ProviderSlotList`：按 `input_schema` 逐条渲染媒体槽（注入角色/上传/素材库/清除），生图 Tab 与视频 Tab 共用；视频源的首帧仍由分镜图自动供给，其余槽位手挂。
- 提交链路：去掉 `exposedKeys` 互斥过滤；`workflow_id` 一律从所选源的 `definition.workflow_id` 取，仅未选源时回退旧分镜遗留值；新增 `keepDeclaredOnly` 只提交该源声明过的键（含 `LEGACY_SLOT_ALIASES` 把 `reference_image` 等单数旧键归并到源声明的复数槽位），切换源后不再残留上一源参数。
- 时长滑杆：名称与范围取该源声明的 `x-std-key=duration` 参数，未声明则用镜头通用范围，不再硬编 3~10。
- 情绪下拉：源自己声明了 `x-role=emotion` 时不再重复渲染，改由源参数表单唯一负责，并把值同步回 `shot.emotion`（配音与剪映导出读该字段）。
- 「参数与暴露」保存/删除后强制重拉当前三个源的 definition 并广播 `provider-list-refresh`。

## 四、待办 / 风险

1. **未做端到端出图**：需要真实 ComfyUI 在线跑一次工作流源生图，确认 31 项参数逐个生效（尤其 `sampling_mode.*` 子键与 LoRA 开关）。
2. `combo_30:16_sampling_mode` 的选项在离线探测时会混进 `{'key': 'on', 'inputs': ...}` 这类字典串（源自 object_info 缺失时的兜底）。schema 侧已过滤，但 `_set_input_guarded` 的枚举自动映射仍可能把 `on` 归到该串上 — 根因在 `auto_detect_exposed_inputs` 的离线兜底，未在本次处理。
3. 画布 `NodeAgentBar` 的参数抽屉与分镜共用 `paramsSchemaToSpecs`，因此同样受益于本次 schema 修复；但它仍只有一个 prompt 输入框，工作流的额外 text 槽位出现在参数抽屉里而非输入区。若要与分镜完全一致，下一步在 `NodeAgentBar` 里把 `x-role` 为 prompt 之外的 text 项也渲染进输入区。
4. `selectedWorkflowId` 现在只服务"未选源"的旧分镜兜底，后续把所有存量分镜的 `workflow_id` 迁成 `image_provider=comfyui_<wf_id>` 后可彻底删除。
5. `ShotInspector.tsx` 工作副本是 CRLF 而 index 为 LF，导致 `git diff` 把整文件 2008 行都算作变更。已将工作副本归一为 LF，真实 diff 约 330 行。仓库缺 `.gitattributes`，建议补一条 `* text=auto eol=lf` 以免后续再次出现整文件行尾漂移。

## 五、第二轮返工（本文以上部分关于"全量摊开"的描述已被此节推翻）

第一轮把 33 项暴露全量渲染成分镜参数表，用户反馈"依然不正确：多参考没显示、特殊情况没处理"。联网对照业界三家后确认方向错误：**自动探测只能用于发现候选，不能等于全都该显示**。

三家共同结论 —— 契约由作者声明、带类型、带语义名：
- ComfyUI 官方 App Mode：`extra.linearMode` + `extra.linearData = { inputs: [[WidgetId, 显示名, config?]], outputs: [NodeId] }`，`WidgetId = "graphId:nodeId:widgetName"`
- ComfyDeploy：图内插显式外部输入节点（`input_id/display_name/description`）
- RunComfy：旁挂 `comfyui-app-script.yaml`

本项目采用官方 App Mode 作为契约载体（用户选定），落地要点：

1. **契约抽取**：`extract_app_contract()` 只在 UI/Save 格式上有 `extra`，API 格式导出会丢掉 —— 因此 `save_workflow` 在格式转换前抽取、`import_external_workflow` 回读外部原文件抽取，统一落到 `meta.app_contract`；图文件始终保持纯节点表（否则 `extra` 会被当成节点，`_apply_dynamic_inputs`/`sanitize` 全部受害）。
2. **契约刷新**：`POST /api/v1/images/workflows/{id}/refresh-app-contract` + 「参数与暴露」里的"重新读取 App 契约"按钮（用户在 ComfyUI App Builder 勾选保存后点一下即可）。`inspect` 响应新增 `app_contract` / `source_file`。
3. **可见性分层**：`apply_app_contract` 给暴露项打 `declared/app_order/作者显示名`；schema 生成据此分层 —— 声明项进基础层并按声明顺序排 priority，有契约却未声明 = 图内部件 → `hidden`，无契约时只保留能语义命名（命中 WF_PARAM_SEMANTICS）的项与自由文本项，其余 `hidden`。`ProviderParamForm` 底部提供"展开内部参数（N 项未在 App 契约中声明）"，不丢白盒。
4. **多参考独立插槽**：媒体暴露项逐条进 `input_schema`（key = `img_<nid>`），带 `x-role`（`character_ref/scene_ref/pose_ref/first_frame/last_frame/control_ref/style_ref/ipadapter_ref`）与 `x-comfy-id/node/param`；标准聚合句柄打 `x-aggregate`。前端 `resolveRenderSlots` 在有逐节点独立槽时不再渲染聚合数组槽 —— 消掉"靠位置猜哪张图进哪个 LoadImage"。
5. **角色判定**：`infer_media_role` 只认作者 label/alias，其次参数名，**不用自动探测的通用描述**（所有 LoadImage 共用"支持上传角色立绘、构图草图…"文案，用它会导致多参考每个槽都判成同一角色 —— 实测踩过）。
6. **嵌套 widget 折叠**：`_write_exposed()` 统一写入入口，`sampling_mode.temperature` 这类折叠进父 widget 的 dict / JSON 子字段；父项不存在则拒绝写入，不再伪造 ComfyUI 不认的扁平键。
7. **位置映射不覆盖显式挂载**：`init_providers` 的 `reference_images → img 槽位`位置映射改为跳过已被显式赋值的槽，用户按节点挂的图不会被聚合数组挤掉。
8. **修第一轮引入的 prompt 绑错**：加了 `"prompt" in label` 之后 "System Prompt" 抢先命中，用户提示词被写进系统提示词节点（wf_4a19b2a2 上实测复现）。现改为用户标记优先、系统标记殿后，并排除 filename_prefix/路径/seed 等机械文本项。
9. **分镜插槽选择器**换成画布的 `CanvasResourcePickerModal`（四源：画布产出/角色库/素材库/本地上传 + 多选累积），原来的 `AssetPickerModal` 是单选且直接覆盖数组 —— 这是"多参考传不进去"的直接原因。

实测（`wf_4a19b2a2`，无契约）：可见参数 32 → **13**（4 基础 + 9 高级），19 项内部件隐藏；`prompt → txt_30:19 (User Prompt)`，`txt_30:18`（系统风格词）与 `txt_30:27_string_b` 作为独立文本参数保留。
多参考三 LoadImage 合成用例：`img_1/img_2/img_3` 分别出 `character_ref/scene_ref/pose_ref` 三个独立槽 ✓；嵌套 `sampling_mode.temperature/top_k` 折叠写入且未破坏父项 `key` ✓。

**下一步**：画布 `NodeAgentBar` 尚未接同一套角色槽位（仍只有一个 prompt 框 + 聚合参考槽），应与分镜对齐；本轮仍未做真实出图端到端。
