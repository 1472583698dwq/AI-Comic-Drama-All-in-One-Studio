## 2.6 自定义代码源 `__import__ not found` + 无独立控件修复（本轮三阶段）

**现象**：自定义源「AutoDL H3 文生视频」生成报 `code compile failed: __import__ not found`，且分镜/画布不显示该源的独立参数控件。

**修复**：

- **沙箱升级** `code_provider.py`：内置受控 `__import__`（`_guarded_import`，黑名单拦截 `os/subprocess/shutil/sys/socket/ctypes/signal/importlib/builtins/pickle/pathlib`，`import a.b.c` 对齐顶层包绑定语义）；补齐常用异常类（`RuntimeError/ValueError/TypeError/KeyError/TimeoutError` 等）；`aiohttp`/`requests` 加入 globals+api（可用 `import aiohttp` 或 `api.aiohttp`）
- **读取路径 schema 兜底** `provider_routes.py:_sanitize_for_frontend`：存量源 `params_schema/input_schema/output_schema` 为空时按 kind 填默认（video：画面比例/分辨率/时长/帧率，不落盘），分镜/画布立即有独立控件，值经 `providerParams→dynamic_inputs→extra→ctx` 透传到用户代码
- **打包** `build_release.py`：`--collect-all aiohttp/requests`（用户代码在 exe 内动态 import，PyInstaller 需显式收集）；`requirements.txt` 补 `aiohttp>=3.9.0 requests>=2.31.0`

## 2.7 AI（MCP/文档导入）生成源防御式缺陷修复（本轮四阶段）

**现象**：画布「生成视频」节点用 AI 创建的「AutoDL H3 文生视频」源执行报 `code execution failed: 'NoneType' object is not subscriptable`。

**真实 API 实测定因**（POST `autodl.art/api/v1/comfyui/comfyui_workflow/{id}`）：

1. LLM 从文档生成的代码 `data["data"]["task_id"]` 硬取下标；当请求参数非法时 API 返回 `{"code":"RequestParameterIsWrong","data":null,"msg":"参数: resolution 的值: 480p 不在 options 列表中"}` → `data:null` 崩溃且服务端 msg 被吞
2. **枚举冲突**：该 API 真实分辨率枚举是 `"480p竖"` 等（竖/横后缀），而通用默认 params_schema 给的是 `["480p","720p","1080p"]` → 下拉一选就触发 1 的崩溃
3. **结果解析错误**：真实轮询结果 `data.results` 是**对象数组** `[{type,url,file_type...}]`，代码当字符串数组取，即使成功也会把 dict 当 url 返回而崩
4. `code_timeout=60s`，而 H3 任务实测 100s → 轮询必超时

**修复**：

- **LLM 提示词防御式契约**（`mcp/server.py` doc→code 与 `provider_routes.py` 文档导入两处）：响应一律 `.get()` 链；业务失败必须 `raise RuntimeError` 带出服务端 code/msg/响应前300字符；列表元素对象/字符串双兼容；轮询设最大次数；API 有自定义枚举时**必须在代码末行追加单行注释 `# PARAMS_SCHEMA: {...JSONSchema...}`**
- **`PARAMS_SCHEMA` 注释解析** `provider_routes.py:_extract_params_schema_from_code`：两个注册路径解析并优先于通用默认 schema——AI 生成源从此自带真实枚举的独立控件
- **video 类 `code_timeout` 默认 600s**（image/audio 120s）
- **存量 `prov_4dc87988` 已重写**：防御式解析 + results 对象/字符串双兼容 + 失败透出 msg + 轮询 300 次×2s；`params_schema` 换为真实枚举 `["480p竖","480p横","720p竖","720p横","1080p竖","1080p横"]` + 时长 + 工作流ID（可换图生视频工作流）；`code_timeout=600`

**验证** `test_code_provider_sandbox.py`（mock 网络复现真实结构）：真实代码成功链路（对象数组→url 提取）✓；复现 `data:null` 场景 → 报错透出 `RequestParameterIsWrong msg=参数: resolution 的值: 480p 不在 options 列表中`（不再是 NoneType）✓；PARAMS_SCHEMA 解析 ✓。

**注意**：排查期间在用户 AutoDL 账号创建了一个真实 t2v 任务（`2ab9abd2`，已 SUCCESS，约 100s 消耗一次生成配额）。

## 2.8 根治：参数契约护栏 + 创建即体检（本轮五阶段）

针对"AI 生成源反复出问题"的共性根因——**参数值不带契约校验就出网，外部系统拒绝后又以最晦涩的方式在远处爆炸**——落地两道闸门：

- **出网前枚举护栏** `code_provider.py:validate_user_params`（2.9 重构后）：三个包装类在 `execute_code_provider` 之前校验**用户显式选择**（`merge_user_params`，dyn>extra）是否落在该源 `params_schema` 枚举内，非法**直接报错且零网络请求**，报错给出合法值列表（与 ComfyUI 注入的 `_set_input_guarded` 对应）
- **ctx 优先级修正**（用户显式选择 > 数据类默认值）：视频 `duration/aspect_ratio/resolution/fps` 原为 `req.duration or extra...`——数据类默认 720p/9:16/24 会**压掉用户下拉选择**；图像源 `dynamic_inputs` 原本**根本没并入 ctx**；音频 `speed/pitch/voice_id` 同病。三处统一改为 `extra/dyn 优先`
- **创建即体检** `code_provider.py:compile_check_code`（零网络/零配额）：python 在**真实沙箱**中编译并定位入口（捕获语法错误/违禁 import/模块级错误/入口缺失），js 做 `node --check`；接入全部四条创建路径（MCP direct_code / direct_definition / LLM doc→code / `/providers/import`）+ `POST /providers/{id}/test`（体检先行快速失败）
- **Agent 闭环**：MCP 注册结果带 `compile_check`，失败时 `status=compile_failed` + `hint`，导演 Agent 当场自我修正而不是等生成时炸

**验证** `test_code_provider_sandbox.py` 5 项：真实代码成功链路 / 服务端报错透出 / PARAMS_SCHEMA 解析 / **非法枚举零请求拦截** / **体检捕获违禁 import+缺入口+模块级错误**。

**残余边界（诚实说明）**：外部 API 若无文档、枚举完全自述，只能靠"真实试一次"验证（test 按钮就是干这个的，会消耗配额）；体系能做到的是让所有不一致**在出网前或创建时**以清晰报错暴露，而不是静默错误+远处崩溃。

## 2.10 去模板收尾：空 prompt 不再误报（本轮七阶段）

**现象**：画布图像节点（ComfyUI 引擎）没有连上游提示词、提示词写在工作流暴露项「输入提示词」里，点生成报 `生图提示词不能为空`。

**根因**：服务端残留去模板前的旧约束——`comfyui.py` 在自定义工作流路径也强制 `req.prompt` 非空；`code_provider.py` 图像源同样硬校验。去模板后提示词的合法来源是上游连线/暴露项/节点覆写，请求级 prompt 为空完全合法（注入层对空 prompt 本就自动跳过）。

**修复**：
- `comfyui.py`：自定义工作流路径允许空 prompt；仅**内置简易工作流**（无 workflow_id，提示词是唯一画面来源）保留校验，报错文案同时给出指引
- `code_provider.py`：图像源移除 prompt 硬校验（prompt 只是 ctx 数据之一，契约由源代码自定义，API 报错会被防御式代码清晰透出）
- 云端 API 源（openai_compat/dashscope/siliconflow/http）保留校验——prompt 是其核心入参，清晰中文报错优于 API 原生错误
- `comfyui_client.py`（内置简易工作流客户端）保留校验

**验证**：真实 ComfyUI E2E——空 req.prompt + 暴露项 `txt_30:19` 携带提示词 → 成功出图 1024x1024；两套冒烟全过；打包版回归 ✓。

## 2.11 导演 Agent 循环一步即停修复（本轮八阶段）

**现象**：导演台 Agent 多步任务只执行一个工具就收工。

**根因**：`AGENT_SYSTEM_PROMPT` 尾部残留单轮 JSON 兜底模式的指令——"请严格输出 JSON（无 markdown 杂质）"+"最多调用 2 个工具"。LangChain 循环（bind_tools 原生 tool calling）里，模型执行完一轮工具后被该指令压制，第二轮直接输出 JSON 总结而非继续调用工具。

**修复**：
- 提示词拆分：`AGENT_SYSTEM_PROMPT_BODY`（工具目录+策略指引主体）+ 两个尾部——`AGENT_LOOP_SYSTEM_PROMPT`（循环模式：新增"多轮执行策略"——目标拆步/逐轮推进/严禁未完成就汇报/工具报错自修正/单轮可并行多工具）与 `AGENT_SYSTEM_PROMPT`（单轮 JSON 兜底专用，保留 JSON 约束）
- `langchain_engine.py`：循环路径 SystemMessage 切换为 LOOP 版；`ainvoke` 加双重试（代理抖动不静默跌落无循环的单轮兜底——另一处"一步即停"来源）；决策解析移出兜底 try；`max_iterations` 6→8（含 WS/SSE 三个入口）

**验证**：两步只读任务（list_custom_providers → list_comfyui_workflows）两轮均执行且总结基于两轮结果；冒烟全过；打包版回归 ✓。注：LLM 代理偶发慢（单轮 ainvoke 可达数十秒），长任务总时长随之增加属正常。

## 2.12 循环无上限化（本轮九阶段）

应用户要求 `max_iterations` 改为**无固定上限**：`run_agent_with_langchain(max_iterations=None)`，`while True` 循环直到模型不再调用工具（目标完成）。防失控双保险：① 连续 3 轮完全相同的工具调用（同名同参，签名比对）判定空转自动收尾；② 绝对安全上限 200 轮（触发时附带"可让我继续"提示）。三入口（WS/SSE/同步）已移除显式 `max_iterations=8` 传参；参数保留，调用方仍可显式限轮。系统提示词同步改为"无固定轮次上限——持续执行直到目标全部完成"。

**验证**：两轮工具任务在无上限模式下正常收敛；编译/冒烟/打包版回归 ✓。

## 2.13 画布生成源输入映射控件（本轮十阶段）

**现象**：视频类自定义源在画布上没有任何输入映射——去模板删掉提示词框后，源 `input_schema` 声明的输入（prompt/first_frame 等）除连线句柄外无 UI 可填。

**修复**：
- 新组件 `ProviderInputControls`：按源 `input_schema.properties` 渲染"生成源输入映射"区——`prompt` 绑节点既有 prompt 状态（上游连线仍优先）、`first_frame` 等图/音/视频句柄渲染本地上传框（绑 firstFrame/ref 状态，FileReader DataURL）、其余 text/number/enum 字段写 `dynamic_inputs` 透传 ctx；数组类（reference_images）仍走连线句柄不渲染
- Image/Video/Audio 三节点接线（状态 `providerInputSchema` 随 providerSchema 一起从 providers 列表/getProvider 获取；Audio 补 `dynamicInputs` 状态并并入 generateTTS extra）
- 后端：代码视频源 ctx 补 `workflow_id` 映射（`user.get('workflow_id') or req.workflow_id`）——此前 params_schema 的「工作流ID」控件值到不了 ctx

**验证**：tsc/vite 构建通过；沙箱 7 项全过；打包版回归 ✓（AutoDL input_schema: prompt=text/first_frame=image 由画布渲染为提示词框+首帧上传）。
