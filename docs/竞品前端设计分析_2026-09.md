# 主流竞品前端设计分析

> **分析对象**：AI 无限画布 / 节点式创作工作台类产品（即梦无限画布、MiniMax Hub、updream、TapNow、Flora、Krea Nodes 等）
> **文档目的**：提炼同类产品的前端**布局骨架、节点卡片形态、输入范式、视觉语言与标志性交互**，对照本项目 `AI 漫剧 Studio` 的现状，输出可落地的界面改进方向。
> **整理日期**：2026-09-26
> **信息来源**：官方站点 + 公开测评/教程文章（含自媒体，见文末附录）。**厂商标称数据（社区工作流数量、用户规模等）未经独立验证**，UI 细节描述部分基于图文测评反推，可能与最新版本存在差异。

---

## 一、结论摘要（TL;DR）

### 1.1 行业已收敛的八条设计范式

| # | 范式 | 说明 | 谁在这么做 |
| :-- | :-- | :-- | :-- |
| 1 | **画布即项目** | 一个项目 = 一张无限画布，所有产物（文本/分镜/图/视频/音频）留在同一空间，取代多窗口切换 | 即梦、updream、MiniMax、Flora |
| 2 | **内容优先的富内容节点** | 节点不是参数表单，而是"可拖拽的功能卡片"：卡片 90% 面积给大图矩阵 / 播放器 / 文本排版 | 即梦、LibTV、TapNow、本项目 |
| 3 | **编辑器脱离画布变换** | 参数表单不随画布缩放平移，固定在底部或侧边（Prompt Composer / 悬浮控制台） | 行业共识，见 §4.3 |
| 4 | **双入口输入** | ① 画布外/内的自然语言输入条；② 选中节点后的就地编辑。二者双向联动 | 即梦、updream、MiniMax、本项目 |
| 5 | **Agent 与画布同图** | Agent 的产物以"文件/卡片"落到画布，而非堆在聊天记录里；人摆节点，Agent 也摆节点 | MiniMax Hub、即梦、Zopia |
| 6 | **Skill / 工作流资产化** | 工作流封装为可复用、可分享、可收益的 Skill，通过 `/` 或广场一键激活 | updream、MiniMax、TapNow |
| 7 | **一致性状态显式化** | 角色/风格锚点用"锁"图标等显式状态表达，一处锁定、下游复用 | updream（锁形图标）、LibTV（主体库） |
| 8 | **导出到专业工具** | 成片环节不硬做，导出剪映/Premiere/DaVinci 工程，用专业软件收尾 | MiniMax（直连剪辑软件）、Mosaic（XML）、本项目（剪映） |

### 1.2 三个分水岭

1. **有没有"底部固定编辑器"** —— 决定画布是"能画"还是"能用"。节点内塞表单的产品，缩放到 30% 后基本不可编辑。
2. **Agent 产物落在哪里** —— 落在聊天窗 = 传统 Chat 工具；落在画布 = 创作工作台。这是 MiniMax Hub 与普通 AI 对话产品的分界线。
3. **一致性是否有显式 UI 表达** —— 只靠 Prompt 描述一致性的，用户必然反复抽卡；有锁定态角标 + 局部重跑的，才形成生产力。

## 二、竞品逐个拆解

### 2.1 国内大厂阵营

#### 2.1.1 即梦 AI 无限画布（字节 / 剪映）

| 维度 | 内容 |
| :-- | :-- |
| **骨架布局** | 网页左侧全局边栏（含"画布"入口）→ 全屏画布区；画布内以"画板"为内容单元，一张画板无限延伸 |
| **内容单元** | 以"画板"承载生成的图/视频/音频，可把素材单独拖出创建新画板，多画板可融合；图像、视频分镜、批量抠图在同一布混排 |
| **输入范式** | Agent 对话模式与画布模式界面一致，一句话指令由 Agent 自动生成整套素材；选图后可继续就地编辑 |
| **视觉语言** | 偏明亮的"创作台"观感，操作记录平铺可视（类比"把 PS 的操作记录铺在画布上"） |
| **标志性交互** | 无限延展画布 + 分镜/素材/成品同屏管理；选中图片一拖即成新画板 |
| **可借鉴** | "一项目一画布"的强心智；**素材就地拖出成新单元**的低摩擦复制 |

> 注：公开测评对即梦画布的**节点连线**描述很少——即梦更接近"无限画板 + Agent 对话"而非"节点连线图"，与 TapNow/LibTV 的显式节点范式不同。这一点在选型时容易混淆。

#### 2.1.2 MiniMax Hub / MiniMax Design（对本项目参考价值最高）

| 维度 | 内容 |
| :-- | :-- |
| **形态** | **桌面端应用**（macOS 13+ / Windows 10+ x64），主打本地化与数据不离本地 |
| **骨架布局** | 极简三块：**聊天区 + 画布区 + 模型/技能入口**。官方描述"界面非常简洁，就是一块干净的画布" |
| **画布承载** | 脚本、分镜、图片、视频、音乐、剪辑**统一在一块画布**，节点自动连线（CANVAS FLOW） |
| **Agent 体系** | 主 Agent 拆任务 → **文案 / 图像 / 视频 / 音频四类子 Agent 并行**；Agent+Harness 在关键节点主动向用户确认方向 |
| **产物形态** | Agent 产物以 **Markdown / 文本 / 图片文件**落到画布，而非对话气泡（用"信息外化"降低工作记忆负担） |
| **输入范式** | **点击画布上的图片 → 直接加入聊天 → 迭代修改**（画布与聊天双向回流） |
| **内置编辑箱** | 重绘、标注、外扩、擦除、高精放大、去背景、色彩调整等 8 项，直接在画布节点上操作 |
| **Skill 体系** | 对话生成专属 Skill；Skill 广场一键调用（分类含短剧、漫剧、动画、分镜、商业广告、电商、音频音乐）；创作者可入驻并收益分成 |
| **资产与衔接** | 画布资料自动本地化 → **资产中心**沉淀；**一键直连专业剪辑软件**；Agent 可调用本地文件 |
| **可借鉴** | ① 四子 Agent 并行的可视化表达；② 产物"文件化"落画布；③ Skill 广场的产品化程度；④ 本地资产中心 |

#### 2.1.3 Seko（商汤）

- **定位**：AI 短剧 / 漫剧创作 Agent，主打**多剧集连续生成**与编导一体。
- **前端特征**：画布 + Agent 混合；多剧集之间的**资产互通**（角色、场景跨集复用）是其界面上的核心表达。
- **可借鉴**：**系列化内容的资产管理视图** —— 不是单项目画布，而是"剧集级"资产的复用面板。对本项目的"多画布 + 角色库"演进有直接参考价值。

#### 2.1.4 可灵 AI / 通义万相 / 海螺 AI（作为对照项）

- 三者**均未真正进入"节点连线工作台"范式**，仍以"单点生成 + 基础画幅延展"为主。
- 公开测评明确指出：可灵"每次生成更像单点加工，镜头之间的承接与项目管理要回到外部表格"。
- **启示**：单点生成能力再强，也替代不了画布的空间组织能力——这正是本项目的机会点，而非短板。

### 2.2 国内垂直创业阵营

#### 2.2.1 updream（B 站自研，2026-04 内测）

界面交互细节是目前公开资料中最完整的，值得逐条对照：

| 界面元素 | 具体设计 |
| :-- | :-- |
| **画布入口** | 首页「新建画布」→ 空白无限画布。**Skill 的多 Agent 协同与上下文记忆仅在画布环境可用**（用能力差异强制用户进入画布） |
| **Skill 唤起** | 画布**左上角搜索框**输入 `/` → 弹出 Skill 菜单 → 「立即激活」；激活后**画布右下角**出现浮动提示卡片；Skill 绑定当前画布上下文，**换画布需重新激活** |
| **加节点** | **双击画布空白处**选择节点类型（图片节点 / 文本节点）；也支持本地文件直接拖入 |
| **连线** | 从一个节点拖出连线到另一节点，自动建立"视觉→语义"关联；**断开连线会导致角色漂移**（把数据流做成了用户可理解的语义） |
| **右键菜单** | 节点右键 → 「生成角色资产图」「生成分镜序列」等**下一步动作**（而非"删除/复制"这类通用动作） |
| **状态角标** | 资产图节点右下角**锁形图标**，点击锁定角色三视图；不锁则每个镜头重新抽卡 |
| **局部重跑** | 单击分镜节点 →「重生成此帧」→ 只刷新该帧并**继承角色锁态** |
| **顶部菜单** | 「预演台」入口在画布顶部菜单栏；生成后得到可交互 3D 白模节点，内置人形占位符可设走位路径 |
| **参数呈现** | 无独立参数面板概念，参数零散在右键/对话框（比例 16:9、2K、时长、镜头数） |

**可借鉴（强烈）**：
1. **右键菜单承载"下一步动作"**——把创作链路做成节点上的动作项，是最低成本的引导设计。
2. **锁形状态角标**——用小图标把"一致性锚点"讲清楚。
3. **Skill 用 `/` 唤起 + 右下角激活提示卡**——轻量、不占版面。
4. **双击空白加节点**——比"左侧节点库拖拽"更快，二者应并存。

#### 2.2.2 TapNow

- **画布形态**：Tapflow 节点式无限画布，从脚本 → 分镜 → 生图 → 生视频 → 配音字幕成片全打通。
- **前端特征**：**TapTV 社区工作流一键克隆**（宣称 12 万+ 公开工作流），深度集成可灵/Seedance/即梦/海螺。
- **节点粒度**：公开评测认为偏"粗粒度功能块"，上手快。
- **可借鉴**：社区工作流克隆 = 把一个工作流实例直接"贴"进我的画布并自动连线，是留存利器。

#### 2.2.3 LibTV

- **节点范式**：明确的节点连线架构，剧本到成片全流程；节点目录化拆分。
- **界面特色**：角色三视图、**主体库**（角色一致性管理）、**多机位 9/25 宫格**（一次出多角度，直接决定分镜选择体验）。
- **可借鉴**：**宫格预览选择器**——生成多候选后，用网格而非单图流呈现，是"抽卡"体验的产品化解法。

#### 2.2.4 OpenCreator

- **方法论**：把生成拆为角色、场景、动作、运镜等**"原子参数"**，节点粒度中等偏细。
- **界面能力**：时间线编辑器、**多轮结果对比**、**局部重跑**。
- **可借鉴**：结果对比视图（同一节点多版本横向排开）是节点卡片内容区的重要形态。

#### 2.2.5 星宇智算（Vera1.1）

- **前端叙事**：画布作为统一信息载体，承接脚本文本、分镜帧、镜头参数、角色锚点，强调"多模块数据同源"。
- **可借鉴**：把**镜头参数（运镜/景别）做成节点上的可见元数据**，而不是藏在参数面板里。

#### 2.2.6 Lovart（LiblibAI）

- **定位**：AI 设计智能体，MCoT 推理引擎 + 统一无限画布。
- **前端特征**：灵感采集、Reference 理解、专业 Skill、**画布上点改**（点击画面局部直接改）、一键转矢量。
- **可借鉴**：**"点改"交互**——选中产物后直接在图上圈选并说需求，是把"对话"降维到画布的关键手势。

### 2.3 海外阵营

#### 2.3.1 Flora

- **范式**：叙事/分镜优先的无限画布，200+ 模型接入，**Story Analysis** 自动分析剧本并提取角色、场景、情绪弧线 → 生成分镜建议；支持**分叉工作流**（Branching）与实时多人协作。
- **可借鉴**：**分叉**——同一节点向下引出多条创意路径并在画布上并排比较；多人协作光标。

#### 2.3.2 Krea Nodes

- **范式**：实时生成节点画布，50+ 模型云端托管；LCM 低延迟，支持 webcam / 屏幕实时输入；2026 新增 **Node Agent**（自然语言自动搭节点工作流）。
- **定位**："给大众的 ComfyUI"，在硬核与易用之间取中。
- **可借鉴**：**实时预览反馈循环**——节点上持续看到中间结果，而非等执行完才出图。

#### 2.3.3 Figma Weave

- **范式**：云端专业画布，**模型无关**统一接入；核心差异是 **App Mode**——把复杂工作流**封装成简易 UI** 供非制作者使用。
- **可借鉴（架构级）**：**"编排者"与"使用者"的解耦**。本项目若有"创作者搭流程 → 运营点击使用"的场景，App Mode 是唯一正解，企业协作/权限/版本控制也在此列。

#### 2.3.4 Mosaic

- **范式**：Tiles（手工节点）+ Agents（自动剪辑/调色/字幕）**双模式同屏**；工作流可**导出 XML 进 Premiere / DaVinci**；支持并行多版本 A/B 测试。
- **可借鉴**：双模式的"切换开关"设计——不是两套产品，而是同一画布上的一个开关（本项目已有"用户自选 / Agent 自主"双模设计，缺少的是界面上的显式切换控件）。

#### 2.3.5 Freepik Spaces / Zopia

- **Freepik Spaces**：云端画布，主打实时多人协作。
- **Zopia**：无节点的多 Agent 全自动出片，光谱另一端。
- **启示**：**节点粒度是产品定位的直接体现**。无节点（全自动）↔ 粗粒度功能块 ↔ 细粒度原子参数，三者对应完全不同的用户群。本项目应明确自己的位置（建议：**粗-中粒度 + 逐节点可下钻**）。

### 2.4 开源参照

#### 2.4.1 ComfyUI

- **地位**：节点式工作流的**事实标准**，社区节点 2400+；工作流 JSON 可嵌入 PNG，成为跨平台交换格式。
- **前端特征**：极端可定制但学习曲线陡；暴露到 VAE 级参数。
- **可借鉴**：工作流**序列化与交换**格式的开放度。

#### 2.4.2 infinite-canvas 系（开源本地工作台）

- **范式**：本地部署的无限画布 AI 创作工作台，把 Prompt、素材、生成结果与多接口（云 API / 本地模型 / ComfyUI 工作流）放进同一画布。
- **可借鉴**：把"多 Provider 接入"直接做成画布上的一等公民节点——与本项目 `ProviderDefinition` 体系同源。

#### 2.4.3 富内容节点 + 底部 Composer 的开源工程范式

公开复刻实战中已跑通并被广泛复用的目录结构，可直接作为本项目重构参照：

```
FlowCanvas            // 画布层：React Flow 容器、节点注册、连线配置
BottomPromptComposer  // 底部固定悬浮编辑器（不随画布变换）
nodes/*               // 素材节点 / 角色节点 / 聚合节点等富内容节点
useSelectedNodeEditor // 选中节点 ↔ 编辑器数据的同步 Hook
```

配套的九条设计约束（原文归纳）：
1. 编辑表单不再作为节点渲染；
2. 表单固定在画布底部中央，**不随画布平移和缩放**；
3. 用 React Flow `Panel` 或外层 absolute overlay 实现；
4. 画布内只保留**素材节点 / 角色节点 / 聚合节点**等"真正的图节点"；
5. 点击节点时，底部 Composer 展示该节点数据；
6. Composer 中的修改**实时写回**节点 data；
7. 视觉风格：**深色半透明 + 大圆角 + 毛玻璃 + 顶部快捷按钮组 + 中部大 textarea + 底部参数工具栏与提交按钮**；
8. 工程拆分如上；
9. 连线方向必须严格：**拖右侧 source handle → 连目标左侧 target handle**。

## 四、共性设计范式提炼与落地要点

### 4.1 布局：三区 + 一浮层

行业稳定解为 **左（资源/节点库）/ 中（无限画布）/ 右（Agent 会话） + 底部悬浮控制台**：

- **左栏**：可折叠，承载节点库、模板、素材库、项目管理；拖拽入画布。
- **中区**：React Flow 画布本体，背景网格 + MiniMap + Controls。
- **右栏**：Agent 会话/导演助手（MiniMax 的聊天区、本项目 `CanvasAgentSidebar`）。
- **底部浮层**：**当前选中节点的编辑器**（Prompt Composer），`absolute` 定位于画布容器底部居中，**不随画布变换**。

**落地要点**：底部浮层的显隐由"选中节点类型"驱动（文本类节点显示 textarea，媒体类节点显示播放器 + 参数行），画布缩放到 5% 时浮层依然可读可编辑。

### 4.2 节点卡片：内容占 90%，参数外置

- 卡片头：图标 + 标题 + 生成源徽标 + 会话标记 + 短 ID。
- 卡片体：大图矩阵 / 视频播放器 / 音频波形 / 富文本排版（**这是节点存在的意义**）。
- 卡片尾：状态与写回（"写回分镜"、锁态、用时/模型标签）。
- 悬浮动作条：选中时出现，含复制/下载/重跑/全屏。
- 右侧 `+` 手柄：向右拉出下游节点（本项目已实现，且与 updream 一致）。

**落地要点**：参数一律不放卡片内；卡片内只留"最高频的一个动作"（通常是"执行/生成"）。

### 4.3 输入：双入口 + 双向联动

1. **底部 Composer**（选中节点后）：技能 Pills → Provider/模型下拉 → 参数插槽 → Prompt 大输入区 → 提交。
2. **节点就地输入**（文本/剧本节点）：卡内 textarea + 快捷技能胶囊。

两者必须**实时双向同步**（改一处另一处立即更新），否则用户会困惑"我到底在改谁"。

### 4.4 视觉语言：深色 + 毛玻璃 + 语义化色板

行业高度一致的做法：
- 深色底（近黑，如 `#0A0A0C`）+ 半透明毛玻璃面板 + 大圆角（12–16px）。
- 品牌主色仅用于**选中态、主按钮、连接线激活态**，不做大面积铺色。
- 节点按类型分色：**用颜色区分节点类别**（图像/视频/音频/文本），并提供 MiniMap 同色映射，让用户在大画布上一眼定位。
- 状态用角标而非文字：锁（一致性）、会话（已被 Agent 引用）、运行中（脉冲光晕）。

### 4.5 画布外置编辑器（最关键的架构判据）

> **编辑表单绝不跟随画布平移缩放。**

实现方式二选一：
- React Flow `<Panel position="bottom-center">`；
- 外层容器 `absolute; bottom: 24px; left: 50%; transform: translateX(-50%)`。

判断标准：把画布缩放到 20%，如果参数还看得清、点得中，说明架构对了；反之，节点内塞表单的实现在这一关就会崩。

### 4.6 引导式交互：右键 = 下一步动作

竞品普遍把**创作链路的下一步**做成节点右键菜单：

```
选中角色资产图 → 右键 → [生成分镜序列] / [生成角色资产图] / [重生成此帧] / [锁定为角色锚点]
```

比"左侧面板找功能"的点击成本低一个数量级，且天然教会用户流程顺序。

### 4.7 一致性状态显式化

- 角色/风格锚点：**锁形图标**，点击锁定，下游节点角标显示"已继承"。
- 局部重跑：单帧/单节点重生成，且**继承上游锁态**。
- 断线即失效：连线被删时给出明确警告（"断开将导致角色漂移"），把数据依赖翻译成创作后果。

### 4.8 Skill / 工作流的入口设计

- **`/` 唤起**：在顶部或左侧搜索框输入 `/` 弹出 Skill 菜单，激活后用**右下角浮动卡片**提示就绪状态。
- **绑定范围可视化**：Skill 绑定当前画布，换画布需重新激活——这个"限制"反而是产品功能，避免上下文串味。
- **社区克隆**：工作流可一键贴入当前画布并自动连线（TapNow / MiniMax Skill 广场）。

## 五、前端技术选型对比

| 方案 | 定位 | 优势 | 代价 | 适配场景 |
| :-- | :-- | :-- | :-- | :-- |
| **React Flow / `@xyflow/react`** | React 节点编辑器组件库 | 自定义节点/边、无限缩放平移、富内容节点渲染、生态成熟（社区约 21.5k star 量级）、官方明确面向 node-based editor | 包体约 95–150KB（gzip 量级）；复杂交互需理解内部状态 | **节点式工作台首选**（TapNow/LibTV 类复刻的最快路径） |
| **Vue Flow** | Vue 版同类 | Vue 3 原生、能力对齐 | 生态小于 React Flow | Vue 技术栈项目 |
| **tldraw** | 无限画布 SDK | "白板"体验完整、原语可拆解、实时协作原生 | 面向自由绘制，节点/连线/数据流语义需自建 | 自由画布 + 批注型场景 |
| **Excalidraw** | 手绘风白板 | 轻量、开源、易嵌入 | 手绘风格与生产工具调性不符 | 草图/评审场景 |
| **AntV X6 / G6** | 图编辑引擎 | 复杂拓扑、泳道图、企业级可视化 | 为"图表"而非"创作卡片"设计，富内容节点改造量大 | 拓扑图、流程图、DAG 运维视图 |
| **Pixi.js / 自绘** | WebGL 渲染层 | 万级节点性能上限高 | 全部交互自建，成本极高 | 超大规模画布 |
| **ComfyUI 式 JSON 工作流** | 序列化格式 | 可嵌入图片、可跨平台交换 | 需要配套解析与版本兼容 | 工作流的导入导出与分享 |

**结论**：本项目当前选择 `@xyflow/react` v12 是行业主流且正确的路线，**不建议更换渲染引擎**；应投入的是"节点抽象、状态管理、性能优化（节点虚拟化）、交互细节收敛"这四件事——这也正是公开复刻实战中被列为"遗留难点"的部分。

## 七、改进建议（按优先级）

### P0 — 直接补齐范式缺口（改动小、收益大）

1. **右键菜单扩展为"下一步动作"**（对照 §4.6）
   在 `NodeContextMenu.tsx` 现有 2 项之上，按节点类型动态生成动作：图像节点 → 生成视频 / 设为角色锚点 / 生成分镜序列；视频节点 → 拼接下游 / 导出片段；音频节点 → 重新配音。实现成本低，引导收益最高。

2. **节点卡片补齐高频动作与状态角标**（对照 §4.2 / §4.7）
   `AgentShell` 悬浮动作条增加"下载 / 重跑 / 全屏"；卡片右下角新增锁形角标（一致性锚点）与会话标记的显式化（当前仅有会话标记）。

3. **快捷键帮助面板**（对照 §4.1）
   复用现有顶部工具条的快捷键提示 pill，点击展开 `?` 面板，列出全部快捷键（当前只有 tooltip）。

4. **清理死代码**：删除或正式挂载 `NodeAgentBar.tsx`；移除未被引用的 `App.css`，避免后续维护误读。

### P1 — 体验升维

5. **多画布页签化**（对照 §2.3.4 / 主流编辑器心智）
   在 `CreativeCanvas.tsx` 顶部工具条把下拉切换升级为**横向页签栏 + `+` 新建**，保留 `CanvasManagerModal` 作为管理入口。

6. **节点分组 / 成组折叠**
   新增 `group` 类型节点，支持框选成组、折叠为一张"剧集/场景"卡片。这是大画布从"能用"走向"好用"的分水岭（Flora 的分叉、Seko 的剧集资产都依赖分组表达）。

7. **底部控制台的双模显式切换**（对照 §2.3.4 Mosaic）
   本项目设计文档已定"用户自选 Provider / Agent 自主编排"双模，但缺少界面上的显式开关。建议在 `NodeAgentConsole` 顶部加入模式切换控件，并让 Agent 模式下的决策结果（选了哪个 Provider、为什么）以可展开的日志行呈现。

8. **一致性锁态的全链路打通**（对照 §2.2.1 updream）
   角色/风格锚点从角色库绑定后，在节点上显示锁形角标，下游节点显示"继承自 #xx"；断链时给明确警告文案。

### P2 — 架构与生态

9. **`CreativeCanvas.tsx` 拆分**（约 1436 行）
   按公开复刻实战验证的范式拆为：`FlowCanvas`（容器与注册）、`nodes/*`（富内容节点）、`BottomPromptComposer`（即现有 `NodeControlBar`）、`useSelectedNodeEditor`（选中态与编辑器数据同步 Hook）。这是后续所有功能增速的前提。

10. **引入轻量 UI 原语层**
    当前弹窗/下拉/按钮全自研且靠约定约束一致性。建议自建或引入 headless 原语（不改变视觉，只统一交互与无障碍），并把 `index.css` 中的主题语义类固化为规范（新代码必须使用 `bg-surface*` / `border-border`，禁止硬编码色值——仓库中已有大量 `[data-theme="light"]` 覆盖规则，说明历史包袱已出现）。

11. **Skill 入口产品化**（对照 §4.8）
    引入 `/` 唤起 + 激活态浮动提示；Skill 与画布绑定，换画布重新激活。项目已有 `SkillStudioModal` 基础，缺的是画布内的高频入口。

12. **工作流导入导出与社区化**
    Provider 体系与 MCP 中枢是差异化优势，可参考 ComfyUI 的 JSON 交换格式与 TapNow 的克隆机制，支持"把某个节点的子图导出为可分享工作流"。
