### 卡片里有什么

1. **内嵌舞台**（`createMiniStage`）：布偶、拖关节（Shift 扭转）、拖空白处环绕、右键平移、滚轮推拉。容器带 `nodrag nopan nowheel`，并拦掉右键菜单和双击（不触发节点菜单 / 双击聚焦）。角标显示「景别 · 焦距」和正在拖的关节（如「主角 · 左肘」）；右上角三个按钮：叠加参考图（有图片参考时才出现）、机位复位到景别预设、关节复位。
2. **预设**：景别 / 运镜 / 焦距 / 速度 / 站位 / 姿态，用的是 3D 片场同一份预设表。选景别时焦距跟着换成该景别的推荐焦距；选姿态会清掉自定义关节（两条都和 3D 片场一致）。
3. **运镜提示词**（`camera_prompt` 输出口），可以复制。
4. **运镜关键帧**（Toonflow）：
   - 记录当前机位为关键帧，或按当前运镜预设一键生成（`motionPresetKeyframes`）；
   - 每帧可以改时间（夹在相邻两帧之间）、切换缓动（平滑 / 线性 / 硬切）、上移 / 下移（机位跟着动，时间保持递增）、删除，也可以用当前机位覆盖这一帧；
   - 可以改总时长（按比例缩放所有帧）；点缩略图回看该帧机位；
   - 预览播放用 `sampleCameraKeyframes`，播放时直接改进度条 DOM，节点不跟着重渲染；
   - 每帧有缩略图，从舞台画布裁出来。

### 上方工具栏

- **导出 PNG**：用 `snapshotPNG`（长边 1280）出图 → 上传到素材库 → 写进 `data.image_url`（`image` 输出口）。
- **导出 MP4**：有 ≥2 个关键帧就按关键帧录，否则按运镜预设录。用 `recordCameraPath` 录制 → 写进 `data.video_url`（`video` 输出口）。
- **新建节点**：缺省会在节点右侧找一个空位，新建一个 `load-image` / `load-video` 节点（通过 `actions.createNodes` 并显式传 `position`、`select:false`，避开已有节点）。参数弹层里可以关掉。
- **在 3D 片场打开**：`actions.navigate('director3d', payload)`，载荷见下文。
- 下载 / 全屏指向最近一次导出的文件。

### 下方面板（PromptPanel）

- 提示词存在 `data.ai_directive`（旧键），用 `useNodeReferences(id, {promptKeys:['ai_directive']})`，所以重排参考时 `{{ref N}}` 会跟着重新编号。
- 发送按钮是「AI 规划」：调 `actions.execute({ai_directive: 拼好的指令, framing, motion, pose, focal_length_mm, camera_roll_deg, cast_layout, speed})`，走宿主原有的 `director_3d_stage_plan` 分支。指令用 kit 的 `assemblePrompt` 拼：自身文本里的 `{{ref N}}` 换成「参考 N」，再附上文本参考的原文，规则与后端一致。
- 图片参考只显示在面板里；另外可以半透明叠加到舞台帧区域，用来对照构图（MCP 不收图片）。
- 生成源下拉只有一项「AI 导演规划 · MCP」。
- 参数弹层里有：画幅（16:9 / 9:16 / 4:3 / 1:1）、环境（简洁地面 + 4 个片场环境）、运镜缓动、荷兰角、「导出时新建节点」开关。

### 决定：`camera_prompt` 用哪一份

- `camera_prompt` 一律用本地 `buildMinimaxCameraPrompt(参数)` 算：改参数即时生效，和 3D 片场 LIVE PROMPT 逐字一致。
- 「AI 规划」只负责改参数（景别 / 运镜 / 姿态 / 站位 / 焦距 / 速度 / 荷兰角）。MCP 返回的 `minimax_camera_prompt` 是英文 label 版，它本身也是参数的确定性函数（LLM 只挑参数），所以丢掉它不丢信息。节点检测到参数变了，就本地重算，把 `camera_prompt` 和 `minimax_camera_prompt` 一起写成同一个值，兼容旧读取方。
- 这次写回单独成一条补丁 `{camera_prompt, minimax_camera_prompt}`，避免旧宿主的 handleNodeUpdate 把别的键一起透传到下游。
- 新节点的 `defaultData` 已经带好算出来的 `camera_prompt`。旧画布节点挂载时会自动补齐。
- 宿主写回后，节点会报出变化，例如「AI 规划（关键词匹配）：景别 中景 → 贴地仰角，焦距 35 → 28mm」。如果宿主什么都没写回（旧宿主出错时只弹 alert、不抛错），节点会提示失败。
- AI 改了姿态但自定义关节还在时，按 3D 片场的规则：姿态预设优先，清掉自定义关节。

### 「在 3D 片场打开」（页面 id / 页签 = `director3d`）

载荷为 `{source:'canvas-director3d', nodeId, shotId?, shotPatch, stage}`：

- `shotId`：节点自己的 `shotId`；没有就取下游第一个带 `shotId` 的节点（「分镜 → 画布」把 shotId 记在视频节点上）。
- `shotPatch`：分镜同名字段 `camera_framing / camera_motion / pose_preset / cast_layout / focal_length_mm / camera_roll_deg / motion_speed / mannequin_pose`。
- `stage`：节点完整的舞台状态，含关键帧、机位、环境、提示词。

**3D 片场页目前不收载荷**：它只跟随 `useProjectStore.activeShotId`，从分镜读这些字段（页面没改）。所以 H1 的 `navigate` 要这样实现，片场才能看到同一套布景：

1. 有 `shotId` 时 `setActiveShotId(shotId)`；
2. 可选 `updateShot(shotId, shotPatch)`；
3. `setActiveTab('director3d')`。

没有 shotId 时只能切页，片场会显示当前分镜。`stage` 留给页面以后直接接收。

## 发现的问题（需协调人 / T3 处理，我在节点侧已绕过）

1. **`scene/stageCore` 在 CSS 缩放容器里拾取不准**
   - 原因：`frameClientRect()` 用的是 `container.getBoundingClientRect()`（屏幕像素，含 React Flow 的 `scale(zoom)`），却加上了 `frame()` 的布局像素（`clientWidth`）。画布缩放 ≠ 1 时，关节拾取的 NDC 会偏。
   - 我的绕法：舞台容器的布局尺寸设为「框 × zoom」，再 `scale(1/zoom)`（zoom 防抖 150ms），让两种像素一致；顺带让放大时画面清晰，像素总量封顶 160 万。
   - 建议的根治：stageCore 按 `rect.width / clientWidth` 换算 frame 偏移。
2. **`recordCameraPath` 停止录制时会丢掉编码器还没处理完的帧**
   - 现象：末帧后只等 `interval*2` 就 `recorder.stop()`。机器忙时（SwiftShader、负载高）视频尾部会被截掉，实测 2.5s 的运镜只剩 1.4s，而且帧时间戳是连续的。
   - 我的绕法：
     - 关键帧末尾加 0.6s 停留再停录；
     - 用 `<video>` 量出实际时长；
     - 完整时交给 T2 `trimMedia(dataURL, 0, 运镜时长)` 精确裁剪（顺带转成标准 H.264），再以 `file_url` 登记到素材库；
     - 仍然不完整时，降到长边 960 重录一次，取较长的那份；如果还是短，就如实提示「设备繁忙丢帧」；
     - 裁剪失败（比如服务器没装 ffmpeg）时原样上传 MP4。
   - 建议 T3 根治：末帧后停止绘制，等编码器清空（例如 0.5～1s 不再画）再 `stop()`，这样节点可以去掉停留和裁剪。
   - 本机无头 SwiftShader 下 1280 长边常被截，960 能完整录下来；真 GPU 下应该不会触发重录。
3. **（与本任务无关，顺带记录）素材库后端 `_attach_file` 只认 png/jpg/webp/mp4… 等扩展名，其他一律存成 `.png`**：3D 片场上传的 `previz.webm` 实际被存成了 `original.png`。本节点只上传 MP4，WebM 会先转码，所以不受影响。
