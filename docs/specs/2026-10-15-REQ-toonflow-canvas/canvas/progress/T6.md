## bug 1：扩展节点跑代码节点报「缺少输入视频」

根因：`engine ext-node → run_canvas_node → build_run_args`（扁平 `{video, prompt, scale}`）→ `ExtensionRegistry._exec_custom_node` 把扁平 args 全当 params、`inputs={}`。

`split_run_args` 规则：
- **扁平形状**（扩展节点、`/extensions/execute` 直调、导出器）：代码节点 `input_schema.properties` 里的键 → inputs，其余 → params；同时也声明在 `params_schema` 的键两边都给。代码节点没有 input_schema → 全进 params（同旧行为）。
- **嵌套形状**（含 `inputs` / `params` dict）：保持旧语义——inputs 原样；没给 params 时取除 inputs 外的其余键；只额外把顶层同名的已声明输入键补进 inputs（不覆盖）。唯一行为差异：`params: {}` 不再把 `{"params": {}}` 自己塞进 params（旧实现的副作用）。
- `input_keys`（扩展节点传入的端口键）：代码节点自己没声明成输入的，inputs / params 两边都给（老节点可能从 params 读）；代码节点声明成参数的只进 params。

调用路径核对：`/extensions/execute`、`run_canvas_node`（引擎 ext-node 分支 + `/canvas-nodes/run`）、`run_exporter` 都经 `extension_registry.execute → _exec_custom_node`，已修；`/custom-nodes/run`、MCP `customnode_<id>`、引擎 custom 分支直接调 `run_custom_node(inputs, params)`，不受影响（MCP 那条本来就按 input_schema 拆）。

## bug 2：DAG 里扩展节点用的是旧输入

根因：`collect_upstream_data` 对 `video` 句柄只写 `videos`/`video_url`，ext-node 分支按端口 id 取 `upstream["video"]` 拿不到 → 回落 `merged["video"]`（节点 data 上前端传播的旧值）。

修法（与前端 `nodes2/legacy-b/{ports,inputs}.ts` 同口径）：
- 端口：ext-node = canvas_nodes 声明 inputs/outputs（`any` → `*`）；custom = input_schema 每个属性（x-handle 媒体 → uri 按键名 → 文本；`type: array` = 多值），无 schema 用兜底三口；输出口按 kind。声明来源：注册表（`canvas_node_manager` / `custom_node_manager`）优先，其次 `data.definition` 快照。
- 落位：targetHandle 必须是声明的输入口（空 handle = 第一个输入口；未声明的口不落值）；单值口 = 最后一条有值的入边，多值口 = 按连线顺序去重的列表。生成源 / 分组来源不落值（生成源 id 仍走原透传）。
- 类型：端口是具体类型时，上游类型明确且不符（如图片 → video 口）不落值；`*` 口按上游推断。
- 取值：执行期 result 优先于节点数据。来源也是 ext-node / custom 时读 `outputs[口]` → 输出口 `from` 键 → 该类型结果键（image_url/result_url、video_url、audio_url、text），读节点数据时跳过与输入口同名的键（N7 遗留 3：upscale_ext 输入口、输出口都叫 `video`，`data.video` 是输入不是产出；上游没跑出结果时不再把它的输入漏给下游）。这条同时作用于生成节点（in 口）读 ext/custom 来源。
- `execute_node` 的 ext-node / custom 分支本来就是「先 upstream 后节点数据」，所以上游重新生成后用的是本次产出。
