## 通用约定

- 前缀 `/api/v1`。成功响应都带 `"status": "success"`。
- **输入 URL** 支持：`/storage/...`、`/exports/...`、`storage/...`；指向本机的 `http(s)://127.0.0.1|localhost:<任意端口>/storage/...`（直接读本地文件，前端 dev 回源后的地址也能用）；外网 http(s)（下载到临时目录，≤512MB、120s，用完删除）；`data:` URI（≤50MB）；storage/exports 内的本地绝对路径。会去掉 `?query`，也会 URL 解码。storage/exports 以外的路径、`..` 穿越、软链出界一律 400。
- **产物**写到 `storage/generated/media_ops/<uuid32>.<ext>`，返回 `/storage/generated/media_ops/...`（与生成源产物同一种 URL，前端用 `resolveMediaUrl` 显示）。原素材不会被覆盖；失败时会删掉半成品。
- **错误码**（`detail` 是可直接展示的中文）：400 参数非法 / 404 素材不存在或画布不存在 / 422 素材处理不了（无视频流、无音轨、坏文件、ffmpeg 报错、下载失败）/ 429 并发已满（同时最多 4 个处理）/ 500 超时或意外异常 / 503 ffmpeg 或 Pillow 没装（带安装指引）。请求体字段类型不对时是 FastAPI 自己的 422。
- 编码：视频统一转 H.264（veryfast, crf18, yuv420p，奇数边补成偶数）+ AAC 192k，输出 mp4 并加 faststart；音频默认 m4a（AAC 192k），可选 `wav`（pcm_s16le）或 `mp3`（libmp3lame）。超时：截帧 90s、音频 300s、视频 900s、探测 30s。

## 接口契约

### `GET /media/ops/engine`
→ `{ffmpeg: bool, ffprobe: bool, pillow: bool, ffmpeg_hint: string}`

### `GET /media/ops/probe?url=`
→ `{status, kind: 'video'|'audio'|'image', duration, width, height, has_audio, has_video, size_bytes}`
（mp3 的封面图不算视频流；图片 duration=0）

### `POST /media/ops/frame`
请求 `{video_url, at?: 'first'|'last'|'time'|'current' = 'first', time?: number}`（`current` 等同 `time`，这两种必须带 `time`）
→ `{status, url(.png), kind:'image', width, height, at:'first'|'last'|'time', time}`
- `time` 小于 0 或超过时长 0.05s 以上 → 400。`time` 离结尾 0.05s 以内，或 seek 后拿不到帧 → 自动改取末帧，此时响应里 `at` 为 `'last'`。
- 输入是纯音频或图片 → 422。

### `POST /media/ops/extract-audio`
请求 `{video_url, format?: 'm4a'|'wav'|'mp3'}` → `{status, url, kind:'audio', duration, size_bytes}`；视频没有音轨 → 422。

### `POST /media/ops/split-av`
请求 `{video_url, format?}` → `{status, video_url(无声 mp4), audio_url, video:{url,kind,duration,width,height,has_audio:false,size_bytes}, audio:{url,kind,duration,size_bytes}}`
- 源视频是 H.264 时直接拷贝视频流，不重新编码（失败再退回重编码）；其他编码一律重编码。没有音轨 → 422。

### `POST /media/ops/trim`
请求 `{url, start, end, format?}`（单位秒，`format` 只对音频有效）
- 视频 → `{status, url(.mp4), kind:'video', duration, width, height, has_audio, size_bytes, start, end}`（有音轨就一起保留）
- 音频 → `{status, url, kind:'audio', duration, size_bytes, start, end}`；没传 `format` 时，wav 源仍输出 wav，其他源输出 m4a
- 必须满足 `0 ≤ start < end`；`end` 超过时长但不到 0.05s 会被截到时长，超出更多 → 400；片段短于 0.05s → 400；输入是图片或视频时传了 `format` → 400。

### `POST /media/ops/speed`
请求 `{audio_url, rate: 0.5–2.0, format?}` → `{status, url, kind:'audio', duration, size_bytes, rate}`
- 用 atempo 链变速，音高不变；输入是视频时只处理它的音轨；输出格式规则同 trim。rate 超出范围 → 400，素材没有音轨 → 422。

### `POST /media/ops/grid-split`
请求 `{image_url, rows: 1–6, cols: 1–6}` → `{status, rows, cols, images:[{url(.png), index, row, col, width, height}], urls:[...]}`
- 结果按行排列，`index = row*cols + col`，行列号都从 0 开始。宽高除不尽时，各块边界按四舍五入分配，所有块拼起来正好是原图。
- 先按 EXIF 方向旋正（和浏览器显示一致），动图只取第一帧，带透明通道的图保留透明。图片太小、不够切 → 400；不是图片 → 422。

### `POST /media/ops/compose-mask`
请求 `{image_url, mask_png: base64 或 dataURL, opacity?: 0.1–0.9 = 0.45, color?: '#RRGGBB' = '#ff3b30'}`
→ `{status, url(.png 标记参考图), kind:'image', width, height, mask_url(.png 二值遮罩：白=重绘区), mask_ratio(0–1)}`
- 判断标记区的规则：遮罩带透明通道时，alpha>0 的像素算标记区；遮罩完全不透明（比如黑底白笔）时，按亮度>0 算。遮罩尺寸和原图不同时会拉伸到原图尺寸。
- 标记区先叠一层半透明色块，再描一圈实色边。描边粗细随图片尺寸等比放大，大图约 12px，小图约 3px。
- 遮罩为空、base64 不合法、opacity 或 color 不合法 → 400。

### `POST /projects/{project_id}/canvases/{canvas_id}/backup`
请求体可选：`{canvas?: {...}}`
- 不带 `canvas`：把 `canvas.json` 里这张画布的原始记录（`name/nodes/edges/updated_at`）再加上 `canvas_id` 写入备份。旧版单画布文件只认 `default`，整份原样备份。
- 带 `canvas`：把传来的 JSON 原样写入备份。前端在迁移前传原始画布，比后端存的那份字段更全。
→ `{status, path:'projects/{pid}/canvas_backups/{cid}-{yyyyMMdd-HHmmss}.json', url:'/storage/<path>', file, canvas_id, source:'stored'|'payload', created_at(ISO 本地时间)}`
- 项目不存在或画布不存在 → 404；`canvas` 不是对象 → 400。项目 id 会先做双 ID 解析（`_resolve_id`），所以内部 UUID 也能用。
- 文件名里非 `[A-Za-z0-9_-]` 的字符替换成 `_`（`cv_xxx`、`default` 不受影响，`..` 会变成 `canvas`）。同一秒内多次备份依次加 `-1`、`-2`…，用 `O_EXCL` 占位防止撞名。每张画布最多保留最近 20 份，更旧的自动删除。

## 画布条目保留 `schema_version` 等字段（协调追加，源自 T4 发现）

**问题**：`manager.save_canvas` 原来只存 `name/nodes/edges/updated_at` 四个字段。T4 迁移时写入的 `schema_version: 2` 一保存就丢了，下次打开会被当成旧画布再迁移、再备份一次。`viewport` 这类字段也会丢。两个 PUT 路由（`PUT /projects/{id}/canvas` 保存、`PUT /projects/{id}/canvases/{cid}` 改名）都是 `body: dict`，本身不过滤字段，所以只需要改 manager。

**改法**（`server/app/providers/project/manager.py`）：
- `save_canvas`：画布条目 = 已存记录里的其他字段，被本次快照的其他字段覆盖，再写入 `name/nodes/edges/updated_at`。所以某次保存没带 `viewport` 或 `schema_version`，已存的值也不会丢；带了新值就覆盖旧值。
  - 以下字段属于容器或请求层，不写进画布条目：`canvas_id`、`project_id`、`version`（存储结构版本，仍在文件顶层）、`active_canvas_id`、`canvases`、`snapshot`。
  - 旧版单画布文件迁移成 `default` 时，也保留原文件里的其他字段。
  - 返回值在有 `schema_version` 时会带上它，即 `PUT /projects/{id}/canvas` 返回 `{status, canvas:{canvas_id, name, schema_version?}}`。
- `get_canvas`：返回值也带上这些字段，例如 `{canvas_id, name, nodes, edges, schema_version, viewport, ...}`。
- `list_canvases`：每一项增加 `schema_version` 字段，没有时为 `null`。前端可以据此判断画布是否需要迁移。
- 顺手修了一个会丢数据的 bug：`save_canvas` 的 `canvas_id` 参数原来默认是 `"default"`。画布 MCP 工具（`mcp/server.py` 里约 7 处）都是先 `get_canvas(pid)` 读出当前画布，改完再调 `save_canvas(pid, snap)`，不传 `canvas_id`。如果当前画布不是 default，就会把这张画布的内容覆盖到 default 上，default 原来的内容就丢了。现在 `canvas_id` 默认为 `None`：没传时用快照里的 `canvas_id`，快照里也没有才用 `"default"`。显式传了 `canvas_id` 的调用（PUT 路由、项目导入）行为不变。

**测试**（在 `test_media_ops.py` 里新增 4 个）：
- `schema_version` 和 `viewport` 能存进去、读出来，`list_canvases` 也有；后续保存不带这些字段时不会丢，带新值时会覆盖；容器层字段不会写进画布条目
- 经路由完整走一遍：直接传快照和 `{snapshot, canvas_id}` 包装两种写法都保留；`GET /canvases` 返回 `schema_version`，旧画布为 `null`；备份文件里也带 `schema_version`
- `save_canvas(pid, get_canvas(pid))` 写回的是当前画布，default 不受影响；快照里没有 `canvas_id` 时仍写 default
- 旧版单画布文件迁移时保留 `viewport`

## 遗留 / 注意

1. **Pillow 不在 `server/requirements.txt`**：本机 venv 装了 12.3，素材库也一直用它（延迟导入）。本任务只能改指定文件，所以没加。没装 Pillow 时，宫格切分和标记合成返回 503 并提示安装。建议后续把 `Pillow` 补进 requirements。
2. **产物不会自动清理**：`storage/generated/media_ops/` 和 `generated/` 一样会一直增长。前端「保存到素材库」需要另走素材库接口，本接口只产出文件。
3. 外网 http 素材由后端下载，和现有 code_provider 的下载一样没有做内网地址拦截（SSRF）。服务默认只监听 127.0.0.1，风险有限；如果放开到局域网，建议加拦截。
4. 设计 §8 写的截帧取值是 `at: 'current'|'first'|'last'`，任务说明写的是 `'first'|'last'|'time'`。两种都支持，`current` 就是 `time`。
5. 音频默认输出 m4a，体积小，云端生成源可以内联（上限 20MB）。如果 IndexTTS 这类本地克隆源对参考音频有要求，前端可以传 `format: 'wav'`；wav 源截取或变速后默认仍是 wav。
6. 8001 隔离实例没有开 `--reload`，看不到本任务的后端改动（新路由、`schema_version` 保留）。E2E 之前需要重启 8001。
7. 接口是同步的：大视频截取会让请求一直等到处理完（上限 900s）。画布素材一般在 1 分钟以内，可以接受；以后要处理长视频，可以改成时间线那种「提交 + 轮询」。
