## 节点定义

```ts
type: 'prompt'   label: '文本'   icon: IconFileText   category: 'text'   width: 220   inPalette: true
ports: in  [VIDEO, IMAGE, STRING]  label「视频、图片、文本输入」   // 同 Toonflow textNode
       prompt [STRING]            label「文本输出」              // 输出口 id 沿用存量连线的 prompt（COORDINATION 1）
defaultData: { text: '', prompt: '', gen_prompt: '' }
```

宽度：Toonflow textNode 不覆盖 nodeSkeleton 默认宽 → **220**（旧 MiniMax PromptNode 是 360）。卡片正文 min-height 110、预览 max-height 240 可滚动（`nopan nowheel`、不可选中，拖预览即拖节点），「编辑」按钮右对齐，空文本时居中；面板 660、工具栏 max-content —— 全部照 Toonflow。

### 数据键

| 键 | 含义 |
|---|---|
| `text` / `prompt` | 正文 Markdown。编辑时**两键同写**；读取 **`prompt` 优先**、空白时回落 `text`（= 下游 `readOutputValue` 与后端 `inputs.source_values` 读到的值；存量 20 个文本节点里 8 个只有 `prompt`）。不定义 `NodeDef.outputValue`，前后端取值不变 |
| `gen_prompt` | **新增**：底部面板的生成指令，含 `{{ref N}}`（`prompt` 已被正文占用）。`useNodeReferences(id, { promptKeys: ['gen_prompt'] })`，参考重排改写的是它而不是正文 |
| `skill_id` | 技能下拉选择：`free_generation`(缺省，不落盘直到用户改) / `prompt_expansion` / `script_generation` / `proposal_generation`；旧值 `custom_text` 显示为自由生成 |
| `agent_state` | `{status: running/completed/failed/idle, tool, error?, updated_at}`，见下 |
| `refOrder` / `refRoles` | kit 约定 |

## execute(overrides)：给 H1 的约定

节点调用 `useKitNodeActions(id).execute(overrides)`，overrides **只作用于本次执行、不要落盘**。键（`skills.TextExecuteOverrides`）：

| 键 | 值 |
|---|---|
| `skill_id` | `free_generation` \| `prompt_expansion` \| `script_generation` \| `proposal_generation` |
| `prompt` | **本次要处理的文本**（已组装）：指令里 `{{ref N}}`→「参考 N」，文本参考按 `参考 N：\n…` 附后（3D 导演机位也当普通文本参考，不分进 camera_prompt），提到图片时附「（参考编号对应：参考 2=第 1 张参考图）」——即 kit `assembleInputs` 的 R6。指令为空时第一条文本参考作主体；指令与文本参考都空时，扩写/拆解/策划案用**当前正文**（自由生成不允许发送）|
| `gen_prompt` | 原始指令（含 `{{ref N}}`） |
| `source_text` | 执行前的正文 |
| `input_source` | `instruction` \| `refs` \| `document`（prompt 从哪来） |
| `reference_images` / `reference_videos` | 图片 / 视频参考 URL（按参考顺序），给多模态 LLM 用 |
| `refs` | `[{n, key, source_id, source_type?, type, value, label?}]` 完整参考快照 |

宿主现有 `handleNodeExecute` 的 prompt 分支读 `d.prompt || d.text`，所以**扩写 / 剧本拆解 / 策划案不改代码即可工作**（处理的是组装后的 prompt，结果写回 `text` + `prompt`）。H1 需要：

1. **新增 `free_generation` 分支**：LLM 按 `overrides.prompt` 生成 Markdown，写回 `{text, prompt}`。现有前端没有通用 LLM 接口（只有固定系统提示词的 `/llm/expand` 和整套 Agent 的 `/agent/chat`），需要 H1/后端加一个（如 `POST /llm/generate` 包 `llm_service.chat_completion`）。现状会落到 else 分支，把组装后的指令原样写进正文。
2. **失败时 reject**（或写 `agent_state.failed`）：现在宿主 `catch → alert()` 后正常返回，节点会把状态记成 completed。
3. 策划案分支：`content` 非字符串时现在写 `text=JSON…`、`prompt=原输入`，两键不一致——请两键写同一个值。
4. 结果补丁里别混非产出键：现 `handleNodeUpdate` 一旦补丁含产出键，就把同补丁里其余键（`agent_state`、`script_data`…）也拷给下游。节点自己写正文时只发 `{text, prompt}`，写状态只发 `{agent_state}`。

### agent_state 协议

- 发送时节点先写 `{status:'running', tool:'text/<skill_id>', updated_at:T0}`；`execute` resolve / reject 后，若宿主在 T0 之后**没写过** agent_state，节点自己写 `completed` / `failed(error)`；宿主写了就以宿主为准。
- 卡片显示：运行中（本地在等，或 `status=running` 且 10 分钟内更新）→ 正文上盖转圈「生成中…」、编辑 / 发送禁用、面板页脚「<技能>中…」；不是本页面发起的运行（Agent 执行、刷新前残留）多一个「不再等待」（写 `idle`）。`failed` → 卡片顶部红色提示（可关闭，换一次失败再出现）。
- MiniMax 文本接口非流式：不做 Toonflow 的逐字追加，完成后整段替换正文。

## 编辑 / 预览（Markdown ⇄ tiptap）

- 卡片：只读预览；「编辑」→ 弹窗编辑；工具栏「全屏」→ 全屏**预览**，弹窗内「预览 / 编辑」可切换（全屏状态保留）。
- 编辑器：富文本 = tiptap（StarterKit + 表格 + 任务列表 + 行内图片 + Placeholder），Markdown 进出用官方 `@tiptap/markdown` 的 MarkdownManager（独立 `Marked` 实例，不改全局 marked）；原文 = textarea 直接改 Markdown。
- **与 Toonflow 的有意差异（正文会原样流向下游当提示词）**：
  1. 序列化不转义 / 不编码：`[中景]`、`1girl_solo`、`2*3`、`a & b` 原样写回（官方实现会写成 `\[中景\]`、`1girl\_solo`、`a &amp; b`）；
  2. 编辑解析不把裸 URL、`<lora:x:0.8>` 当链接（否则被改写成 `[x](x)`），输入时不自动转链接；预览里 `<lora:…>` 按原文显示，http 链接仍可点；
  3. 删除线只认 `~~x~~`：单个 `~` 常见于「3~5 秒」，GFM 会把两个范围之间渲染成删除线（预览与编辑都改了）；
  4. `isRichSafe`：解析再序列化与原文一致（忽略空白 / 块间空行）才默认富文本，否则默认原文编辑并提示（表格对齐、`_斜体_`、`*` 列表、转义符、HTML 等）；打开 / 切换模式都不回写，只有在富文本里真的改了才按规范重写全文；
  5. 预览单换行即换行（marked `breaks`）：剧本拆解结果是逐行文本；
  6. 单图段落被 @tiptap/markdown 拆成块级 image（它假设图片是块级），这里图片是行内节点，`wrapInlineBlocks` 重新包进段落保证 schema 合法。
- 预览安全：DOMPurify（禁 style/form/button/textarea/select、去事件属性与 `javascript:`），只留 text-align 内联样式，外链 `target=_blank rel=noopener noreferrer`，复选框只读，相对产物图片 `resolveMediaUrl` 回源。

## 工具栏 / 面板

- 上方：添加到素材库（宿主 `saveToAssets`；无正文或 `canSaveToAssets=false` 置灰）｜ 复制文本 · 下载 `<标题>.md`（选中且有正文时生成 Blob 链接，变化/取消选中即回收）· 全屏阅读。用 `topSlot` 自建 FloatingToolbar 以便按正文是否为空控制禁用。
- 下方 PromptPanel：参考列表（拖拽排序；点文本参考 → 只读弹窗看全文，点图片/视频 → `openFullscreen`）、`{{ref N}}` 输入（占位文字随技能变）、技能下拉（LLM：自由生成；技能：扩写 / 剧本拆解 / 策划案）、发送（⌘/Ctrl+Enter）。提示：引用了暂无内容的参考 → 不能发送（同 Toonflow）；未引用的空参考「已跳过」；编号越界「请重新引用」；扩写/拆解/策划案连了图片视频 →「只处理文本，参考 N 不会使用」。

## kit 问题（请协调人统一改）

1. `PromptPanel` 的下拉写死「生成源」：按钮 aria-label、搜索框「搜索生成源」、空列表「暂无可用生成源…」。文本节点拿它当技能下拉，建议加 `sourceLabel`（如「技能」）和 `searchable`（4 项不需要搜索框）。
2. `PromptPanel` 传 `running` 但不传 `onStop` 时显示一个**禁用的停止图标**（title「停止生成」）。宿主执行不可取消，建议此时显示转圈（Toonflow `:loading`）。文本节点目前不传 `running`，改用 `disabled` + 页脚状态文字。
3. `PromptPanel.warnings` 只有危险色一种样式；「只处理文本，参考 2 不会使用」这类提示更适合中性色，建议支持 `{text, level}`。
4. `useNodeReferences` 缺省改写非 audio 节点的 `prompt` 里的 `{{ref N}}`；文本节点的 `prompt` 是正文，必须传 `promptKeys: ['gen_prompt']`。宿主若有别处替节点改写编号，文本节点也要用 `gen_prompt`。
5. `FloatingToolbar` 在宿主没给 `saveToAssets` 时整个隐藏「添加到素材库」（Toonflow 是置灰）。

## 遗留 / 需要其他任务配合

1. **H1**：`free_generation` 分支与通用 LLM 接口；失败 reject；策划案两键一致；结果补丁不要把 `agent_state`/`script_data` 传给下游（见上「execute」1–4）。`saveToAssets(nodeId)` 对文本节点应保存正文 Markdown，`canSaveToAssets` 按正文是否为空。
2. **后端（T5 范围）**：画布 MCP `canvas_execute` 在服务端执行文本节点时，技能输入是 `data.prompt`（正文）+ 参考，而新界面的输入是 `gen_prompt`。建议 `engine.execute_node` 的 prompt 分支：`gen_prompt` 非空时用它（`{{ref N}}` 按 inputs R6 组装）作技能输入，空时保持现状；并补 `free_generation` 分支（现在未知技能原样透传正文，无害）。
3. 正文 `text` 与 `prompt` 都有且不同的存量数据（迁移告警的 text-prompt）：节点显示 `prompt`（与下游一致），第一次编辑后两键统一。
4. 编辑弹窗是模态的，没做完整焦点循环（Tab 可能移出弹窗）；Esc / 点遮罩关闭可用。
5. Toonflow 的「正文落盘到工作区 assets/<id>/content.md、重新读取磁盘」不适用 MiniMax（正文存在画布 JSON），未移植。
