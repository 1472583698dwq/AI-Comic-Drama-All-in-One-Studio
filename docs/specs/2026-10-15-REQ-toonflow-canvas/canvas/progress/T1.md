## 与后端组装规则的一致性（协调人 10-15 要求）

`assembleInputs` / `buildRefs` 按 `server/app/canvas/inputs.py` R1–R7 重写：
- 自动模式只对 `video`：0 图→text（只有音/视频参考→multiReference）、1→singleImage、≥2→multiReference；非视频目标未指定的图一律进 `reference_images`；旧值 i2v/r2v/t2v 归一（i2v+首尾帧记 startEnd）。
- 提示词：主体 = 节点自身文本（audio 取 `text` 优先，其余 `prompt` 优先，`{{ref N}}`→`参考 N`）；自身为空时第一条文本参考作主体不加前缀；其余 `参考 N：\n…`；去掉与自身相同的文本参考；附「参考编号对应」；段落 `\n\n`，多条机位 `\n`。
- 参考边：`in` 口，或 in 口节点类型的空口/旧具名口；排除 provider*/group 来源；`source|sourceHandle` 去重；refOrder 优先其余按连线顺序；空值参考也占号。缺 sourceHandle 时按 `PRIMARY_OUTPUT_PORT` 读取（键仍用原始 sourceHandle，与后端 edge_key 一致）。
- 取值键与后端相同（STRING：prompt→text→brief…；3D 导演机位读 camera_prompt/minimax_camera_prompt；IMAGE：image_url→result_url→file_url→thumb_url…）。
- 文本节点输出口 id 为 `prompt`（COORDINATION.md 第 1 条），样例已按此。
- `__tests__/assembleInputs.test.ts` 的「前后端同一夹具」三组用例逐条照搬 `server/tests/test_canvas_in_port.py`（旧具名口 vs in+refRoles 同结果、自动分配各模式、顺序与提示词），期望值与后端一致。

**有意的前端差异**：①按生成源 maxItems 截断 + warnings（截断后「参考编号对应」只写仍下发的图）；②后端判断不出类型（kind=None）时前端再看注册表声明的端口类型；③`NodeDef.outputValue` 覆盖是前端扩展点——**谁用了它，要同步改后端 `inputs.source_values`**；④批量图（一条参考多张图）不支持——迁移已把 `load-image-batch` 拆成单图节点。

## 集成（H1）须知

1. `<ReactFlow className="cv-canvas ${isLight?'light':'dark'}" colorMode={...}>`：React Flow 的 colorMode 会给包裹层加 `.light`，会触发 MiniMax `.light` 变量块，必须跟随应用主题（现有 CreativeCanvas 已这么做）。
2. `nodeTypes={nodeTypesMap()}`、`isValidConnection={isValidConnectionFactory(rf.getNode, getNodeDef, { getEdges: rf.getEdges })}`；`defaultEdgeOptions={{ type: 'simplebezier' }}`、`connectionLineType=SimpleBezier`；`snapGrid=[16,16]`、`minZoom 0.2`、`maxZoom 8`；`<Background variant=Dots gap=16 color="var(--cv-border)" bgColor="var(--cv-canvas-bg)"/>`。
3. 与选中 / 拖动节点相连的边由宿主加 `className: 'cv-edge-active'`（主色）；点边的 32px 断开按钮宿主渲染，可用 `.cv-edge-disconnect` 样式。
4. 宿主用 `<CanvasHostProvider>` 注入 `updateNodeData`（建议用宿主自己的、带下游传播的那个）、`saveToAssets/canSaveToAssets`、`remove`、`openFullscreen`、`refresh` 等；不注入时 kit 回落 React Flow（复制/副本/删除/改名可直接用）。
5. 节点右键菜单由 NodeSkeleton 自己弹（会 `stopPropagation`，宿主的 `onNodeContextMenu` 收不到）；要用宿主菜单就给 NodeSkeleton 传 `contextMenu={false}`。
6. `<SelectionToolbar/>` 放进 `<ReactFlow>`；要接撤销历史用 `apply` 接管提交。拖动结束可调 `reparentOnDrop(nodes, draggedIds)` 实现 Toonflow 的拖入/拖出分组。
7. 生成：`const a = assembleInputs({ refs, targetType: node.type, prompt: ownPromptOf(node.type, data), mode: data.mode, refRoles: data.refRoles, slots: extractSlotsFromProvider(provider, kind) })`，下发用 `a.args`（+ 视频 `mode: a.providerMode`），面板展示 `a.warnings`、`slotOf = item => a.assignments[item.key]`。
8. 参考重排时 `useNodeReferences` 同步改写节点自身文本里的 `{{ref N}}`：缺省 audio 改 `text`+`prompt`，其余改 `prompt`（`useNodeReferences(id, { promptKeys })` 可覆盖）。PromptInput 打开时也会自行回写新编号。

## 遗留 / 说明

- 分组标题：字号 12px、离框 8px（照 Toonflow；design「框外上方 12px」理解为字号）。四角缩放把手 `autoScale=false`（随画布缩放，同 Toonflow），缩得很小时较难点中。
- NodeSkeleton 不会在端口变化时自动删除悬空连线（Toonflow 会删）——避免迁移遗漏时静默丢线；端口变化只调用 `updateNodeInternals`。
- 生成源下拉 / 参数弹层 / 右键菜单都是 portal 到 body 的 kit 自带弹层，没有用现有 UI 库。
- 浮层在拖动中、框选中、多选时隐藏（Toonflow 是拖动后直到再次点击才恢复，这里松手即恢复）。
