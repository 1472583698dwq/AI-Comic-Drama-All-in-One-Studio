## 端口

- `load-image`：`in`[IMAGE]「来源图片」（Toonflow 同款，只做来源连线：标记产物从原图 `image` 连进来；不读取其值）、`image`[IMAGE]。
- `image`：`in`[IMAGE, STRING]、`image`[IMAGE]。

## 数据键

**load-image**：`image_url` + `image` + `url` 三键同写（`readOutputValue` 先读端口同名键 `image`，只写 image_url 会被旧 `image` 遮住）；`asset_id`（上传 / 从素材库拖入的素材 id，换成别的图时清空）；`history`（局部重绘后出现）；局部重绘用 `inpaint_prompt`、`inpaint_provider_id`、`inpaint_params`、`inpaint_model`（带前缀，不与下游混淆）；重绘时执行器还会写 `agent_state`、`result_url`、`width`、`height`；产物节点带 `_origin: {op:'grid-split'|'mark'|'character', from, …}`。

**image**：`prompt`（旧数据有 `text` / `idea` 镜像时一起改）、`provider_id` + `provider`、`params` + `provider_params`（并把后端执行器先读的 `aspect_ratio/resolution/steps/cfg/seed/style_preset/negative_prompt` 镜像到顶层；ComfyUI 工作流的几十个参数不铺顶层）、`model`、`image_url` + `result_url`、`history`、`refOrder`、`refRoles`、`smart_plan`（缺省 false）、`skill_id`、`agent_state`、`_last_agent_plan`、`polished_prompt`、`inpaint_prompt`、`width/height`。

## 行为

- **尺寸**：有图时卡片宽 = 240×宽高比 + 18（夹在 100–720+18），图片高 240；无图 220。
- **上传 / 替换**：≤100MB、仅图片；走素材库 `POST /assets`（返回 `/storage/assets/<id>/original.*`），见下「偏差」。素材库拖入沿用拖拽契约（`application/canvas-assetid` + `text/plain` 绝对 URL → 还原成 `/storage/...`），文本素材 / 非图片不拦截（交给画布）；拖入本地图片文件也会上传。节点内 drop 会 `stopPropagation`，宿主画布不会再建节点。
- **标记**：涂抹层画好 → `mediaOps.composeMask(image_url, 涂抹层PNG, {opacity:0.9, color})` → 右侧 80px（竖向避让）新建 `load-image`「<名> - 标记」，并从本节点 `image` 连到它的 `in`（Toonflow saveMark 同款）。
- **局部重绘**（两个节点都有）：涂抹（红 #ff4545，55% 显示）+ 重绘要求 → `composeMask(..., {opacity:0.55})` 得引导图 → `useGeneration().run({kind:'image', smartPlan:false})`，参考图 = [原图, 引导图, …用户参考]，提示词 = Toonflow 重绘说明 + 要求（用户 `{{ref N}}` 自动后移 2 位，附「参考编号对应」），输出比例自动取最接近原图的枚举 → 生成结果在浏览器端按涂抹蒙版贴回原图（区域外像素不变，Toonflow 同款）并落盘 → 写回当前图片，新图进历史版本、原图保留在历史里可切回。贴回失败（跨域等）时直接用生成结果并提示。生成源放不下 2 张参考图时阻止并提示。
- **宫格切分**：`mediaOps.gridSplit` → `actions.createNodes(N 个 load-image, {select:false})`，标签「<名> · 行-列」，Toonflow 版式：锚点右侧 80px、列距 = 块节点宽 + 40、行距 320、整体压到已有节点时下移。
- **图片生成**：`assembleInputs({refs, targetType:'image', prompt: ownPromptOf('image', data), refRoles, slots: extractSlotsFromProvider(def)})` → `gen.run({nodeType:'image', kind:'image', data, assembled, providerId, params, smartPlan, intent: assembled.prompt})`；停止 = `gen.cancel()`。生成源下拉首项「Agent 自动选源」（provider 为空，只能配合智能规划，否则发送置灰并提示）。智能规划结果在面板头部显示「智能规划 · 源 · 参数」。运行中卡片遮罩 + 停止按钮；失败写 `agent_state.failed`，面板 / 卡片显示原因并 toast。陈旧的 running（>20 分钟，刷新页面后）不再算运行中。
- **历史版本**：≥2 版时卡片下方出现缩略条，点选即切换 `image_url`（load-image 三键）——下游 `readOutputValue` 拿到的就是当前版本。替换图片（上传）也记入历史（Toonflow 同款）。
- **角色一致性**：技能选「角色一致性」后面板出现项目角色（`useProjectStore().project.characters`）：点角色 = 绑定主图，「三视图」= 绑定其余视图 → 在左侧新建 `load-image`（`_origin.op='character'`）并连到本节点 `in`，进入参考列表；智能规划开启时随请求下发 `skill_id`。
- 参数改动即时写回（Toonflow 同款，不再有「应用」草稿）。

## 与 Toonflow / 任务描述的偏差（有意）

1. **上传通道**：任务说「沿用 LoaderNodes 的上传接口」，但旧 LoadImageNode 用的 `/images/comfyui/upload` 只把文件推进 ComfyUI input 目录、返回 ComfyUI 内部文件名（ComfyUI 不在线直接 500，浏览器 / 生成源也取不到），所以改用 MiniMax 里能拿到可访问 URL 的那条：素材库 `POST /assets`（CanvasResourcePickerModal 的降级路径、3D 片场导出、N3 视频节点同款）。上传的图会进当前项目素材库（category=other、标签 canvas），节点记 `asset_id`。宿主可用 `setImageUploader(fn)` 换通道。
2. **标记颜色单色**：compose-mask 只接受一种颜色，所以颜色对整层生效（改色即全部重绘成新色，所见即所得）；Toonflow 是逐笔颜色。描边由后端加，细笔画会略粗。
3. **局部重绘结果落盘**：浏览器合成的 PNG 用 `mediaOps.gridSplit(dataURL, 1, 1)` 落到 `storage/generated/media_ops/`（1×1 切分 = 原样存 PNG，不进素材库）。建议后端加正式的「保存 / 蒙版贴回」接口后替换（`upload.ts persistDataUrl` 一处）。
4. 局部重绘不走智能规划（重绘说明不能被 LLM 改写），面板隐藏开关与技能。
5. 没做 Toonflow 的「历史记录」对话框，用卡片内历史条代替（任务要求的 strip）。

## kit / 协调问题（请协调人统一改，N2 已在节点侧规避）

1. COORDINATION 第 7 条写 `useGeneration(id, actions.update)`，但签名不同：useGeneration 要 `(nodeId, patch)`，`actions.update` 只收 `patch`（直接传会把 id 当补丁写进去，TS 也会报错）。N2 用包装函数。
2. `useKitNodeActions().canSaveToAssets` 在 `useMemo([host, rf, nodeId])` 里算一次，节点数据变了不更新——生成出图后「添加到素材库」仍是灰的。建议改成每次读取（getter / 函数）。
3. RefList / PromptInput 的缩略图直接用 `/storage/...` 相对地址，dev（51xx）下 404。N2 传给面板的参考已 `resolveMediaUrl`（K1 修好后两边都兼容）。
4. `useProviderSources` 不订阅 `invalidateProviderSources()`，清缓存后列表不会重拉。N2 在下拉展开时 `loadProviderSources({refresh:true})`。
5. `executeAgentNode` 把 `{...node.data, ...override}` 合并后：①先铺持久化的 `data.params` 再按声明键从合并结果补缺 → 本次 `params` 被持久化参数盖掉；②声明的槽位键会从节点里的**旧值**补上（断开连线后旧图仍发出去）。N2 用 `generationData()` 剔除旧槽位键 / `text` / `idea` / `img_*`，并把本次参数写进 `data.params`；建议 useGeneration 统一做（K1 的 `stripStaleSlotKeys`）。
6. `patchFromPayload` 生成后把 `aspect_ratio` 写成 `"832:1216"` 这类像素比，后端执行器先读顶层 `aspect_ratio`，下次 `canvas_execute` 会带非法比例（N2 改参数时会覆盖回枚举值，但生成后又被写脏）。
7. `CreateNodesOptions` / `NewNodeSpec.position` 注释写「绝对坐标」，但 `createNodesLocal` 让新节点继承锚点 `parentId`，等于按父分组相对坐标。N2 传的是**锚点同坐标系**（与 createNodesLocal 一致），H1 实现时请对齐。
8. 宿主没有「把新节点连进锚点」的能力（`connectFrom` 只能从锚点连出）。角色绑定用了 `useReactFlow().addEdges`（受控画布走宿主 `onEdgesChange`）。
9. PromptInput 的 placeholder 只在编辑器创建时生效；N2 切换「生成 / 局部重绘」时给 PromptPanel 加 `key` 重建。
