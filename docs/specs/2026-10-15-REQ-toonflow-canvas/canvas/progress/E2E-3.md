## 失败用例与根因

### D4：分镜子图自动运行出片后不回写分镜

- 现象：shot#1 绑定 comfyui_video 后，右键「使用新画布生成视频」。子图建好，3D 导演规划和视频生成都执行了，视频节点在 13:12:53.802Z 写入 `video_url=/storage/videos/mock_fb3669f5.mp4`（status completed，用时 494ms）。但同一秒弹出「已在画布建好子图，视频未自动产出，请在视频节点内手动生成」，分镜的 `video_url` 仍是 null。连续两轮（B、C）都复现。
- 根因：`client/src/components/canvas/CreativeCanvas.tsx:673-684`。
  - 第 673 行 `await execute(sub.videoNodeId)` 返回后，第 678 行马上读 `nodesRef.current` 里的视频节点 data。
  - 但 `nodesRef.current` 只在渲染时赋值（第 145 行 `nodesRef.current = nodes`）。生成结果是通过 `updateNodeData → setNodes` 写进去的，React 要到下一次渲染才提交。
  - 所以 await 之后读到的还是旧 data，没有 `video_url`，代码走进了第 684 行的 info 分支，不会调用 `writeBackToShot`。
  - 另外 `host/executeRouter.ts:237` 把 `runHostGeneration` 返回的 `{url}` 丢掉了，`execute` 只返回 void，调用方拿不到产物 URL。
  - 任何生成源都会走到这一步（视频轮询结束时同样是先 `updateNodeData` 再返回），所以这条成功路径一定失败。H1 只验证过失败路径。
- 建议修法（任选其一）：
  - `execute` 透传 `runHostGeneration` 的 `{url}`，`runShotOnCanvas` 直接用返回的 url 回写；
  - 或者 `updateNodeData` 在 `setNodes` 的回调里同步更新 `nodesRef.current`；
  - 或者 await 之后先等一帧，再从 `rf.getNode()` / `nodesRef` 读取。
  - 修完建议补一条单测：mock `runGeneration` 成功，断言调用了 `writeBackToShot`。
- 已通过的部分：
  - 绑定全部正确（见 D4 细节）。
  - 手动回写正常：在视频节点右键「回写到分镜…」，点「回写视频」后提示「已回写 分镜 #1 · 视频」，`content.json` 里的 shot.video_url 也更新了。

### D5：Agent 的 canvas_execute 结果不落到画布节点

- 现象：
  - Agent 依次调了 `canvas_create_node(image, provider=comfyui)`、`canvas_connect(slot=prompt)` 和 `canvas_execute([image])`。
  - 工具返回 `image_19121_661: {status: success, image_url: /storage/generated/gen_1792070411_….png, elapsed_ms: 85870}`。
  - Agent 最后回复「指令已执行」，但画布上的图片节点仍是空白占位（见 `D5-final.jpg`）。
  - 落盘的 canvas.json 里这个节点没有 `image_url`、`agent_state`、`history`，聊天里也没有产物（artifacts 为空）。
- 根因：
  - `server/app/mcp/server.py:2909-2922`：`canvas_execute` 只执行 `execute_dag` 并把 results 返回给 Agent，不会把各节点的产出合并进画布快照（`_save_snap`）。`canvas/engine.py` 本身也不落盘。
  - 前端在 `agent-canvas-updated` 时重载 canvas.json（`CreativeCanvas.tsx:571-585`），文件里本来就没有结果，所以节点是空的。
  - `agentEventReducer.ts:201` 会派发带 result 的 `agent-canvas-tool` 事件，但全仓库没有监听者。
  - 基线 f76838b 的代码与现在相同，是既有缺陷，不是本需求引入的。但它导致 D5 的「生成成功」在画布上看不到。
- 建议修法：
  - `canvas_execute` 执行完后，把每个 `status=success` 的结果按节点类型合并进节点 data，再 `_save_snap`，并触发 `canvas_updated`。要合并的内容：`image_url` / `video_url` / `audio_url` / 文本、`agent_state.completed`，并追加 `history`。
  - 或者前端监听 `agent-canvas-tool`，在 `tool=canvas_execute` 时用 `updateNodeData` 回填。
- 已通过的部分：
  - 节点与连线正确：边 `targetHandle: "in"`，`refRoles = {prompt_e2e3_cat|prompt: "prompt"}`，`refOrder` 正确。
  - 生成真实执行：ComfyUI 本地出图。

## 其他发现（不属于上面的用例断言，按严重度排序）

1. **【高｜既有】`canvas_execute(target_ids=[X])` 会把兄弟生成节点也重跑一遍**
   - D6 只让 Agent 执行视频节点 V，结果引擎把 V 的上游文本节点的另一个下游（D5 的图片节点）也执行了，又调了一次 ComfyUI（35s）。
   - 原因：`server/app/canvas/engine.py:1011-1020` 的闭包是「target 的上游祖先」再加上「整个闭包的下游」，祖先的其他下游也被算进去了。基线代码相同。
   - 如果兄弟节点用的是付费源，会产生意外扣费。
   - 建议：下游只从 `target_ids` 本身展开，祖先只用来取数据。
2. **【中｜环境】内置 `comfyui` 生图源会把中文提示词原样送进 SDXL（waiIllustriousSDXL）的 CLIPTextEncode**
   - 证据是 PNG 内嵌的 prompt：负向词里没有 NSFW 约束，模型也看不懂中文。
   - D5 中「一只橘猫…」生成了与提示词无关的**露骨图片**。我已删除这两张图（`gen_1792070411_*`、`gen_1792070779_*`），截图里也做了打码或避开。
   - 建议：comfyui 源加英文化或扩写步骤（或默认开智能规划），负向词加 `nsfw`。
3. **【低｜开发环境】音频节点波形在跨域 dev 下加载失败（「当前音频无法显示波形」，console 报 CORS）**
   - 推测的根因：
     - `nodes2/audio/AudioPlayer.tsx:266` 的 `<audio src preload="metadata">` 没设 `crossOrigin`，按 no-cors 请求，请求不带 Origin。
     - 后端 CORS 中间件只在请求带 Origin 时才加 `Access-Control-Allow-Origin` 和 `Vary: Origin`，这次的响应两样都没有，被浏览器缓存了。
     - 随后 `waveform.ts:100` 的 `fetch(url)`（cors 模式）命中这份缓存，被浏览器拦截。用 curl 带 Origin 直接请求能拿到 ACAO。
   - 同源部署不受影响。
   - 建议：`<audio crossOrigin="anonymous">`，或 `fetch(url, {cache: 'no-store'})`。可能影响 B9。
4. **【低】迁移后的一次性去重叠（`resolveOverlaps`）在媒体尺寸确定前就执行了**
   - 视频卡片在视频加载后会变高，结果仍和下面的节点重叠（`D3-unknown-node-zoom.jpg`：「无类型节点」压在视频生成卡片底部）。
5. **【低】备份文件缺少原画布条目的 `updated_at`**
   - 前端把 `get_canvas` 的输出作为 payload 传给备份接口，而 `get_canvas` 不含 `updated_at`。nodes / edges 与原文件逐字节一致。
   - 建议备份接口改为优先用已存条目（`_read_stored_canvas_raw`），或者两者合并。
6. **【低｜既有】首页「导入剧本」在已有活跃项目时只会跳到画布，弹窗不出现**
   - `views/HomeView.tsx:178-191`：`goCanvasIfProject()` 已经切走了页签，HomeView 随之卸载。本需求没有改这个文件。
   - 从顶栏「⋯ → 导入小说」打开是正常的。
7. **【低｜既有】3D 片场「截屏入队」并导出白模后，监视器（PiP）画面缩成 14×24 像素**
   - 监视器面板里多了队列缩略图和提示文字，`pipBox` 被挤到很矮，ResizeObserver 随之缩小渲染尺寸。本需求的 diff 没有改 PiP 相关代码。
   - 另外，白模截图会把选中框和 gizmo 一起拍进去（`D4-A-canvas.jpg` 的白模节点）。
8. **【低】Agent 用 `canvas_create_node` 指定的坐标经常让节点互相重叠**（D6 的 A/B 两个 load-image）。
