## 导出 API

- `migrateCanvas(raw) → { canvas, changed, report }`
  - `report = { converted: {'旧->新': 原节点数}, rewiredEdges, unknownTypes, warnings, providerEdges, droppedEdges, createdNodes }`（后 3 项是追加的）
  - 输出 `schema_version: 2`；输入 `schema_version >= 2` 原样返回同一对象、`changed=false`
  - `changed` 只反映内容改动，补 `schema_version` 不算
- 常量：`CANVAS_SCHEMA_VERSION`、`NEW_IN_PORT='in'`、`LEGACY_SLOT_MAP`、`SLOT_PRIORITY`、`IN_PORT_NODE_TYPES`、`GENERATION_NODE_TYPES`、`PRIMARY_OUTPUT_PORT`、`PROVIDER_NODE_TYPES`、`LEGACY_TYPE_MAP`、`LEGACY_NODE_TYPES`、`CURRENT_NODE_TYPES`、`LOAD_IMAGE_WIDTH`、`BATCH_SPLIT_SPACING`
- 函数：`edgeKey(edge)` / `edgeKey(source, sourceHandle)` → `source|sourceHandle`（空句柄为空串）；`legacySlotFor(handle, oldTargetType?)`；`toInPort(targetType, targetHandle, sourceType?)`（宿主/Agent 连线兼容：返回 `{targetHandle:'in', role?}` 或 `null` 表示原样保留）；`detectAssetMediaKind(data)`
- 类型：`RefSlot`、`CanvasNodeLike`、`CanvasEdgeLike`、`RawCanvas`、`MigratedCanvas`、`HistoryEntry`、`MigrateReport`、`MigrateResult`

## 实际实现的映射

### 节点类型

| 旧类型 | 新类型 | data 处理（只补缺失键，不覆盖、不删除；都加 `_migrated_from`） | 输出口 |
|---|---|---|---|
| `text-prompt` | `prompt` | `prompt`/`text` 缺一补一；两者都有且不同 → 都保留并告警 | `prompt`、`text`、空 → `prompt` |
| `video-legacy` | `video` | `prompt←video_prompt`；`first_frame←first_frame_url\|image_url`；`provider_id`/`provider←provider_id\|provider\|provider_video`；`mode`（i2v/r2v/t2v）原样保留 | 空、`video` → `video` |
| `tts` | `audio` | `text←dialogue\|subtitle_text\|brief`；`prompt←text`；`provider_id`/`provider←provider_id\|provider\|provider_audio\|audio_provider`；`voice_id←voice`；`ref_audio←reference_audio\|ref_audio_path`；`emotion`、`voice_id` 原样（执行器按生成源声明键取） | 空、`audio` → `audio` |
| `asset` | `load-image` / `load-video` / `load-audio` | 媒体类型：`video_url`/`audio_url`/`image_url` → `media_type`/`asset_type`/`mime_type`/`kind`/`type` → `file_url`/`url`/`file_path` 扩展名 → 有 `thumb_url` 或图片类 `category` 记为图片 → 判断不出按图片并告警。补 `<kind>`、`url`、`<kind>_url`（取 `<kind>_url\|file_url\|url\|thumb_url`） | 任意口 → 对应类型唯一输出口 |
| `load-image-batch` | N 个 `load-image` | 每张：其余键复制 + `image`/`url`/`image_url`=该图 + `_batch:{from,index,total}`；首张 `_batch.legacy` 保存被挪走的 `images`/`image_list`/`image`/`url`/`image_url` 原值；`measured`/`selected` 等节点级 UI 态不带过去 | 出边逐张复制（`${edgeId}__${i}`），源口 `image` |
| `brief`、`timeline-export` 及其余独有类型 | 不变 | — | — |
| 不在 `CURRENT_NODE_TYPES` 里的类型（含无 type 的节点，记为 `default`） | 原样保留 | 列进 `report.unknownTypes` | — |

- 批量拆分的 id：首张沿用原 id，其余 `${id}__${i}`（撞 id 时追加 `_2`…）；横向间距 `260 + 40`（260 同 `autoLayout` 的 `EST['load-image']`）；N = max(1, 图片数)，空批量变成一个保留原 id 的空图片节点。
- 老 3D 导演组件（`AssetNode.tsx` 里的 `Director3DNode`）输出口 `camera` → `camera_prompt`。

### 连线

- 目标是单输入口节点（`IN_PORT_NODE_TYPES` = `prompt`/`image`/`video`/`audio`/`director3d`）且 `targetHandle !== 'in'`：
  - 目标口是 `provider`，或源是 `provider*` 节点 → 原样保留，计入 `providerEdges` 并告警；
  - 其余 → `targetHandle:'in'`；源口缺失时补成源节点主输出口（如 `load-image` → `image`），保证 edgeKey 与新连线一致；
  - 槽位 `legacySlotFor`：`prompt`/`text`→`prompt`，`reference`/`reference_images`/`images`/`image_list`→`reference_images`，`first_frame(_url)`→`first_frame`，`last_frame(_url)`→`last_frame`，`camera_prompt`，`ref_audio`/`reference_audio`/`ref_audio_path`→`ref_audio`，`reference_video`；`video-legacy` 的 `image` 口→`first_frame`；空句柄不指定槽位（交给 assembleInputs 按模式分配）；表外口名原样作为槽位名并告警。
  - 写入目标节点：`data.refRoles[edgeKey] = 槽位`（已有的不覆盖）；`data.refOrder` = 已有 refOrder + 已存在的 `in` 连线 + 本次改连的连线，按槽位优先级 `prompt → camera_prompt → first_frame → last_frame → reference_images → ref_audio → reference_video → 表外槽位 → 无槽位` 排；同槽位内按目标节点旧数组（如 `reference_images`）里的 URL 顺序，再按原连线顺序。
  - 同一输出口连了同一目标的多个旧口（如图片既是首帧又是参考）：改连后保留优先级最高的一条，其余记进 `droppedEdges` 并告警（目标节点上的旧槽位数据仍在）。
- 其他节点（export、timeline、timeline-export、shot-card、custom、ext-node…）的具名口一律不动；连线 id、数组顺序不变。

### history

`image`/`video`/`audio` 节点没有 `data.history` 时，用 `image_url|result_url` / `video_url` / `audio_url|result_url` 起一条 `{url, created_at?=agent_state.updated_at, provider_id?=provider_id|provider|agent_state.provider_id}`。

## 遗留 / 需要其他任务配合

1. **后端存盘不保留 `schema_version`**：`server/app/providers/project/manager.py::save_canvas` 只写 `name/nodes/edges/updated_at`。迁移本身做到了「内容幂等」（已迁移画布再跑 `changed=false`，所以不会重复备份），但 D2 要求的 `schema_version: 2` 落盘需要 T2/H1 让 `save_canvas` 保留该字段。
2. **`schema_version >= 2` 不再迁移**：之后 Agent 经 MCP 写入的旧口名连线不会被前端纠正，依赖 T5 的 `canvas_connect` 兼容（可复用同一套映射：`LEGACY_SLOT_MAP` + `video-legacy.image→first_frame`）。
3. **文本节点输出口**：design §6.1 写的是 `text`，但存量 18 条连线全用 `prompt`，任务要求新节点沿用旧输出口 id，迁移按 `prompt` 处理（`PRIMARY_OUTPUT_PORT.prompt='prompt'`）。N1 的输出口要用 `prompt`，否则需要同步改这里。
4. **`director3d` 也改连 `in`**（design §6.1 其端口为 `in[STRING,IMAGE]`），N5 须使用 `in`。
5. `refRoles` 里除 design §4 的槽位外还会出现 `prompt` 和表外的旧口名（生成源插槽键）；assembleInputs 应把未知槽位按同名生成源插槽处理。
6. `video` 节点的旧 `mode` 值（i2v/r2v/t2v）原样保留，N3 需把这些值当作「自动」或做映射。
7. 拆分出的图片节点横排在原位置右侧，可能与右边已有节点重叠（迁移时不知道新卡片实际尺寸）。
