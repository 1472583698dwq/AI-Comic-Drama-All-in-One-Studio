## 行为

### 视频 `load-video`
- 上传 / 替换：≤100MB、`video/*`（Toonflow 限制）。MP4 走素材库 `createAsset`（同 `CanvasResourcePickerModal` 的音视频通道，带 `project_id`），**非 MP4 走 `/agent/upload`**（素材库 `_attach_file` 只认 .mp4 等扩展名，.mov/.webm 会被存成 .png）。替换不删旧文件。
- 素材库拖入：认 `application/canvas-assetid` + `text/plain`（素材库 / 工作台卡片）、`text/uri-list`、系统文件；按扩展名判视频（后端素材分类没有 video，视频素材是 other）；本机后端绝对地址归一成 `/storage/...`。接受的拖拽 `stopPropagation`（宿主画布 onDrop 不会再建节点）；文本素材 / 节点面板拖拽不拦截。
- 工具栏（Toonflow 顺序）：添加到素材库（宿主）· 提取音轨 · 分离音视频 · 截取片段 · 替换视频 | 截取视频帧 ▾ · 下载 · 全屏。播放器控制条里也有截帧菜单。
- 截帧：当前帧（播放头秒数，`at:'time'`）/ 首帧 / 尾帧 → `mediaOps.extractFrame` → 新 `load-image`（`image_url`+`image`+`url`，`width/height/frame_time/source_video`），标题「源标题 · 当前帧/首帧/尾帧」。
- 提取音轨 → 1 个 `load-audio`（`audio_url`+`audio`+`url`+`duration`，「· 音轨」）；分离音视频 → 静音 `load-video`（「· 静音视频」）+ `load-audio`；截取片段 → 新 `load-video`（「· 1.00–3.00 秒」）。
- 产物**不连线、不改变当前选中**（`createNodes(specs, {select:false})`，Toonflow 同款）；源节点是顶层节点时按 Toonflow 摆放算好 `position`（右缘 + 40/80、与右侧节点重叠则下移、多个产物竖排 300/320），源节点在分组里时不给坐标交给宿主。
- 取消处理 = 停止等待、丢弃结果（`/media/ops/*` 是同步接口，已开始的会跑完，产物不落节点）。视频换了会自动关闭弹窗、丢弃进行中的处理。
- 尺寸：Toonflow resizeVideo，宽 = max(180, 240×宽/高) + 18；元数据没到时先用落盘的 width/height。

### 视频生成 `video`
- 卡片：当前结果播放器（同上，含截帧）或空态 IconCameraAi；生成中 / 排队中 / 恢复中遮罩（不挡拖动）；失败或宿主复位留下的 `agent_state.error` 显示在卡片下；保留了 `_taskId` 且未完成时出「重新查询」。
- 工具栏：提取音轨 · 分离音视频 · 截取片段 · 历史记录 · 替换视频 | 截帧 · 下载 · 全屏（Toonflow 同款）。历史「设为当前结果」只改 `video_url`（下游拿当前版本）。替换视频进历史。
- 底部 PromptPanel：参考列表（`useNodeReferences`，卡片底部显示实际去向）、`{{ref N}}` 输入、生成源下拉（`useProviderSources('video')`，按 内置 / ComfyUI / 自定义 分组）、参数按钮（摘要「比例 · 分辨率 · 时长」+ 比例小框）、智能规划开关、发送 / 停止；`assembled.warnings` + 「生成源不在可用列表」显示在面板告警区；有参考时首行显示「模式：X（自动）· 说明」。
- 参数弹层：生成模式（`自动（X）` + `availableModes(slots)`，当前显式值不受支持时也列出并标注）；时长（`duration` 的 enum 或 minimum..maximum 整数）+ 分辨率（`resolution` enum）；通用比例 16:9/9:16/1:1/4:3/3:4（缺省 9:16；写生成源声明的 `aspect_ratio`/`ratio`/`aspect`，有 enum 时不在其中的置灰、多出的值如 adaptive/21:9 追加；未声明时以 `aspect_ratio` 下发）；生成音频（`generate_audio` 等布尔参数存在时）；其余参数 `DynamicControl`（去掉已在快捷区的键，带 Agent 可填 / 建议 / 手填徽标）。
- 切生成源：清 `_last_agent_plan/_taskId/_polling`，参数 = 新源缺省 + 旧值里对新源仍合法的比例 / 时长 / 分辨率 / 生成音频（Toonflow 切模型保留比例）。
- 模式「自动匹配」（Toonflow）：kit `autoMode`（0 图文生、1 图单图、≥2 图多参考，与后端一致）不被所选生成源支持时退到能用的：1 图且只有参考图槽 → 多参考；≥2 图且没有参考图槽 → 首尾帧（再不行单图）；生成源不收图 → 文生。与 kit 一致时传 `mode:''` 给 assembleInputs（保持后端 R7 语义），不一致时才传显式模式；**不写回 data.mode**。
- 发送：`useGeneration().run({ nodeType:'video', kind:'video', data: dataForRun(...), assembled: assembleInputs({refs, targetType:'video', prompt: ownPromptOf('video', data), mode, refRoles: data.refRoles, slots: extractSlotsFromProvider(def)}), providerId, params: data.params, smartPlan: data.smart_plan, intent: assembled.prompt })`。直接生成要求选了生成源；智能规划可不选（Agent 选源）。智能规划回写的 params 再同步一次 engine 顶层键。停止 = `gen.cancel()`（+ 停恢复轮询）。
- `dataForRun`：交给执行器的数据去掉本次组装没有的旧槽位键（`first_frame/last_frame/reference_images/camera_prompt/image/text…`）与生成源 input_schema 键——否则 `buildAgentArgs` 会从节点顶层把断开的首帧、旧连线拷来的文本悄悄下发。
- 重启恢复：挂载时 `_polling===true && _taskId`（旧数据回落 `_last_agent_plan.task_id`）→ `pollVideoTask` → 写 `video_url` + `history` + `agent_state:completed` + `_polling:false`；失败写 `agent_state:failed`。宿主若加载时把 `_polling` 复位（旧 CreativeCanvas 行为），卡片出「重新查询」手动恢复。

## 发现的 kit / 其他问题（未改，交协调人）

1. **RefList / PromptInput 直接用 `item.value` / `item.thumb` 当 `src`**：`/storage/...` 相对地址在 dev（vite 51xx ≠ 后端）下 404。本节点给面板传了 `resolveMediaUrl` 后的展示用参考（组装仍用原值）；建议 kit 在 RefCard / RefAtom 内部统一 `resolveMediaUrl`，N2/N4 同样会踩。
2. **`assembleInputs` 单图模式不看生成源能力**：未指定槽位的第一张图固定先进 `first_frame`，生成源只有参考图槽时随后被截断丢弃（告警「生成源不支持首帧」），而 `availableModes` 对只有参考图槽的源也列出 `singleImage`。本节点在**自动**模式下已按能力绕开；用户显式选「单图参考」+ 只收参考图的源仍会丢图。建议 singleImage 在没有 first_frame 能力时落参考图。
3. **自动模式不看能力（与后端一致）**：Toonflow 的自动匹配是看模型支持的模式的。本节点前端做了能力兜底（见上），但后端 `canvas_execute` 路径仍是能力无关的 autoMode——对「只有首尾帧槽」的源（如海螺首尾帧类）两条路径会不同（前端首尾帧 / 后端多参考→参考图被该源忽略）。需要的话 T5 的 inputs.py 也按生成源能力兜底。
4. **执行器从节点顶层补入参**：`nodeAgentExecutor.buildAgentArgs` 按生成源 input_schema 的键、旧 nodeRegistry 句柄键从节点顶层补值，且 `text` 优先于 prompt；迁移后的旧节点 data 里残留的 `first_frame/reference_images/camera_prompt/text/image` 会被悄悄下发。本节点用 `dataForRun` 过滤；建议在 `useGeneration.runGeneration` 里统一做（图片 / 音频生成节点同样受影响）。
5. **`readOutputValue` 的 VIDEO 兜底键 `['video','url']`**（与后端 `source_values` fallback 一致）：存量旧视频节点的 `url` 是上游图片地址（旧传播拷入），`video_url` 为空时会被当作该节点的视频输出。建议迁移时清掉这类拷入键，或兜底时检查扩展名 / 类型。
6. `useProviderSources` 没有刷新入口：`invalidateProviderSources()` 只清缓存，已挂载的 hook 不会重拉。
7. `useProviderDefinition` 换 id 时不先置空，加载期间返回上一个源的定义；本节点按 `def.id === providerId` 过滤。
