## 两处调研不一致的修复（design §6.2）

1. **ext-node**：注册了 `getPorts`，kit `isValidConnectionFactory` 直接按声明校验（视频→`video` 可连、图片→`video` 红色拒绝、未声明口拒绝）；值按声明端口 id 落位：`edgeInputPatch({source:'v1',sourceHandle:'video',target:'ext',targetHandle:'video'})` → `{video: url}`（不再是 `video_url`）。节点「运行」时还把 `collectDynamicInputs` 的结果作为 `execute` 的 overrides 交给宿主，宿主没做传播也能让后端按端口 id 取到值。作为上游时 `outputValue` 读 `outputs[端口]` → `data[from]` → 结果键，**不会把同名输入口 `data.video` 当成产出**（upscale_ext 输入口与输出口都叫 `video`）。
2. **custom**：注册端口（`getPorts`）、卡片渲染、传播、执行全部走 `customNodePorts(data)`（input_schema 为准）；旧 nodeRegistry 写死的 `first_frame / ref_audio / reference_images…` 不再出现（测试里对照 `NODE_SPECS.custom` 断言）。定义晚到时组件按缓存版本号重算端口。

## 给 H1 的接入说明

1. `import './legacy-b'`（由 `nodes2/index.ts` 汇总）即完成注册；`nodeTypesMap()` 自然包含这 9 个类型。
2. 连线校验：kit `isValidConnectionFactory(getNode, getNodeDef, {getEdges})` 已足够（动态端口走 `getPorts`，`canConnect=rejectProviderSource` 拒绝把 `provider` 口接到 ext/custom/provider/script-split）。需要单独拿端口时用 `resolveDynamicPorts(node)`（非本目录节点回落 kit 注册表）。
3. 传播（替代旧 `onConnect` / `handleNodeUpdate` 里按 nodeRegistry 猜键的逻辑）：
   - 连线时：来源是生成源 → `providerPatchFor(src)`（`{provider_id, provider, model?}`）；目标是 ext/custom/provider → `edgeInputPatch(edge, src, tgt)`；
   - 上游产出变化 / 加载画布后：对目标是动态端口节点的出边 `collectDynamicInputs(tgt, edges, getNode)` 整体重算；生成源 `provider_id/model` 变化时对其出边再发一次 `providerPatchFor`（旧宿主只在连线那一刻透传）；
   - 生成节点（N2–N4）若想限制「生图源只连图片生成」，可在其 `canConnect` 里用 `providerKindMatches(src.node, targetType)`（`isRefEdge` 已排除 provider 来源，不会进参考列表）。
4. `execute(nodeId, overrides)`：沿用 `CreativeCanvas` 原分支（custom → `/canvas/node/execute` 或 `executeAgentNode` 的 `/custom-nodes/run`；ext-node 去掉 `definition` 再发），把 overrides 合进本次 data。**需要补一处**：`script-split` 的引擎结果是 `{project}`，现分支只回写 `image_url/video_url/audio_url/prompt/text/outputs`，请加 `if (node.type==='script-split' && rr.project) patch.result = rr.project`，失败写 `error`（节点也兼容直接读 `data.project`）。旧版宿主「拆解后自动生成分镜卡」早已被移除，按钮文案「一键拆解并生成分镜卡」照旧保留，是否恢复由 H1 决定。
5. `refreshCustomNodes` 拿到列表后可调 `registerCustomNodeDefs(list)`（不调也行，节点自己会拉）。
6. 生成源节点发 `open-provider-create` 时 `source = 'provider-node:<nodeId>'`，只有发起的那个节点会在 `provider-created` 时选中新源。

## 与旧组件的差异（都是修问题，功能不减）

- `provider-llm` 列 LLM 源、写 `kind:'llm'`（旧的落成生图源，引擎也当 image）；LLM 源不显示「扩展新生成源」（创建弹窗不支持 llm）。
- 重新拉生成源列表不再把用户调过的 `params` 重置为默认值（只在用户换源时重置，同旧）；列表里的最新定义仍同步回 `data.definition`。
- 生成源参数改用 DynamicControl（旧的是裸 input）；保存参数 / 删除源后广播 `provider-list-refresh` 并清 kit 生成源缓存。
- 新建源只选中发起节点（旧的会让画布上所有生成源节点一起选中）。
- 生成源节点旧的隐藏兼容入口 `config`（1px 透明、可连）不再声明：git 历史里从未有代码连它，引擎 / 传播也不读；存量画布 0 个 provider 节点（T4 盘点）。
- custom / ext 的文本输入框改为「每个未连线的文本输入口一个」，写端口 id 键（旧的是一个框同时写 `prompt`+`text`）；结果文本只在 `text` 不是输入口时显示。
- 拆解结果摘要按全部场次数分镜（旧的只数第一场）。
- 媒体预览经 `resolveMediaUrl`（开发环境相对 URL 不再 404）；错误提示用 toast 代替 `alert`。
- AI 润色弹窗挂到 body（旧的渲染在画布 transform 内，会随缩放 / 平移错位）。

## 遗留 / 需要其他任务配合

1. 🔴 **后端阻塞 C6（ext-node 跑示例插件）——不是前端问题**：`upscale_ext` 的执行链 `engine ext-node → run_canvas_node → build_run_args`（产出扁平 `{video, prompt, scale}`）→ `ExtensionRegistry._exec_custom_node` 把扁平 args 全当 `params`、`inputs={}` → `upscale_demo` 报「缺少输入视频」。实证（8001）：`POST /extensions/execute {"id":"custom_node:upscale_demo","args":{"video":…}}` → 失败；`args:{"inputs":{"video":…},"params":{"scale":2}}` → 成功。前端已把 `video` 送到端口 id 上（见上面请求体），仍然失败。建议改 `server/app/extensions/registry.py::_exec_custom_node`：没有 `inputs` 键时按定义 `input_schema.properties` 的键把扁平 args 拆成 inputs / params（或 `build_run_args` 对 `custom_node:` 目标产出嵌套结构）。
2. 后端 `engine.collect_upstream_data` 对 ext-node 目标的入边仍按旧句柄名启发（`video` 口写成 `video_url/videos`），DAG 执行时实际靠节点 data 上已落的端口值；建议对 ext-node 目标按声明端口 id 写 `upstream[port.id]`（否则上游重新生成后用的是旧值）。
3. `outputValue` 覆盖（ext-node / custom）是前端扩展点（T1 约定需同步后端 `inputs.source_values`）：后端执行期优先读上游 result（`video_url` 等），常见情形一致；只有后端回落读节点 data 时，`data[端口 id]` 可能是**输入值**。建议后端对 ext-node 来源先读 `result.outputs[sourceHandle]`、对 custom/ext 来源跳过与输入口同名的键。
4. kit 没有卡片内表单控件样式：本目录用 `.cv-lb-*`（`legacyB.css`），N6 的 legacy-a 也各自做了一套、也各自搬了一份回写分镜控件；DynamicControl 的 `--cv-*` 配色覆盖（`.cv-lb-dyn`）N2–N4 的参数弹层同样需要。建议协调人统一上提到 kit。
5. 自测时 8001 的 `canvas_custom_nodes` 功能开关是关的（`/custom-nodes` 404）：custom 节点显示「自定义节点列表不可用：…」，端口用样例定义；开关打开后的列表 / 运行留给 E2E C5。
