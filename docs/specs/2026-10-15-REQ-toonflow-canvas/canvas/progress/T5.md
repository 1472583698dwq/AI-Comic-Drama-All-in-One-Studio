### 画布 MCP 工具

- `canvas_connect`：目标是 `prompt/image/video/audio/director3d` 时一律存成 `targetHandle:'in'`；槽位优先级：`slot` 参数 > 旧端口名映射 > 自动。写 `data.refRoles[edgeKey]`，`edgeKey` 追加到 `data.refOrder`（refOrder 缺失或不全时先按现有参考顺序补齐，新参考不会插到旧参考前面）。省略 `sourceHandle` 时补源节点主输出口（与 T4 迁移一致）。同一 edgeKey 再连：不加重复边，给了 slot 就更新（status `updated`），未迁移的旧具名口边就地改成 `in`。显式 slot 与上游类型不符 → 报错；旧端口名与类型不符 → 改自动并在 `note` 说明。连 group → 报错。返回 `ref_key / ref_index / slot / slot_source / refs`。其他节点（export/timeline/custom…）行为不变。
- `canvas_create_node`：支持 `type:'group'`（`children` 子节点 id、`label` 标题；子节点全不存在则报错，部分不存在列在 `missing_children`）；旧类型 `text-prompt/tts/video-legacy` 直接建成 `prompt/audio/video`；生成类节点默认带 `refOrder: []`、`refRoles: {}`。
- `canvas_query`：新增 `inputs[node_id]` = 有序参考列表（`n/key/source/source_type/kind/slot/assigned_by/value`，可能有 `ignored`、`value_slots`）和 `input_model` 说明；摘要里列出分组和每个生成节点的参考。
- `canvas_delete_node`：删分组只删框（子节点释放）；删任意节点时清理下游 `refOrder/refRoles` 里的残留键。
- 所有 `canvas_*` 写回读出来的那张画布（显式传 `canvas_id`），不再写进 `default`；`schema_version`、`viewport` 等顶层键随快照保留（配合 T2 的 `save_canvas` 改动）。
- 工具描述/参数：`canvas_connect` 加 `slot`（enum），`canvas_create_node` 加 `children`、`label`，其余描述补充新模型说明，向后兼容。

## 组装规则（前端 `kit/assembleInputs.ts` 应与之一致）

见 `server/app/canvas/inputs.py` 模块文档 R1–R7。与当前 `assembleInputs.ts` 的差异（需要前端对齐，W3 校对）：

1. **视频自动模式 2 张图**：后端 → `multiReference`（两张都进参考图，同 Toonflow「普通媒体优先作为参考」）；前端 `autoMode` 现为 `startEnd`。
2. **提示词**：后端 own 为空时第一条文本参考作主体、不加 `参考 N：` 前缀（否则 Agent 新建的「文本 → 音频」会把「参考 1：」念出来）；与 own 完全相同的文本参考去掉（迁移后的旧节点 data.prompt 是连线时拷贝来的同一段文本，不去重会重复）。前端现在每条文本都加前缀、不去重。
3. **非视频目标的图片**（image/audio/prompt/director3d）：后端未指定槽位的图一律进 `reference_images`；前端在未选生成源（宽松能力）时单图会落到 `first_frame`。
4. 只有音频/视频参考、没有图时后端记 `multiReference`，前端记 `text`（只影响模式显示，不影响落位）。
5. 后端不做 maxItems 截断（不知道生成源能力），这是预期差异。

**T6 追加（协调人拍板，前端 K1 同步）R6a 音频目标的配音文本**：只对 `type=audio` 生效，其他目标仍按 R6。
- 不加「参考 N：」前缀，也不加「（参考编号对应…）」附注；
- 自身文本（`text` 优先，其次 `prompt`）非空 → 只念自身文本，其中 `{{ref N}}` 换成第 N 项文本参考（prompt 槽）的**原文**；N 不是带值的文本参考（媒体 / camera_prompt 槽 / 越界 / 空值）→ 换成空串，结果 trim；没被 `{{ref N}}` 提到的文本参考不念；
- 自身文本为空 → prompt 槽的文本参考按参考顺序用 `"\n"` 连接（空串丢弃，无前缀）。
- 实现：`inputs.assemble_audio_text`；用例 `test_canvas_in_port.py::TestAudioText`。

已与前端一致的点：`refOrder` 排序、序号含空值参考、director3d 文本 → `camera_prompt`（任何目标）、显式槽位与类型不符视为未指定、单值槽先到先得、`{{ref N}}` → `参考 N` 加「参考编号对应」附注、camera 多条 `\n` 连接、段落 `\n\n` 连接。

## 遗留 / 提醒

- 8001 实例是不带 reload 启动的，要看到本任务的后端改动需要重启它。
- `canvas_connect` 不会顺手迁移目标节点上其他旧具名口连线（前端加载时由 `migrate.ts` 统一迁移）；后端执行器两种都认。
- 后端认的旧口名比 `migrate.ts` 的 `LEGACY_SLOT_MAP` 多几个（`brief/image_prompt/video_prompt/reference_image/ref/reference_audios/audios/reference_videos/videos`）；迁移把这些当未知口名原样写进 refRoles 时，后端仍能归一到正确槽位，前端会按未指定处理（媒体类型相同时结果一样）。
- 同一来源输出口连了两个旧具名口（如同一张图既连首帧又连参考集）时，新模型只能保留一个槽位（T4 迁移合并为一条），这是数据模型决定的。
