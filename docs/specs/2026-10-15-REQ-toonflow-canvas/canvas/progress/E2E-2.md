## 失败用例与根因

### B8：自动「多参考」+ comfyui_video 必定失败

**复现**
- 两个图片节点连到视频生成的 `in`，生成源选「ComfyUI 视频 (本地)」，面板显示「模式：多参考（自动）」。
- 点发送，节点报错：`✗ 图生视频模式需要 first_frame_url (首帧图)`（截图 `b8-08-multiref-failed.jpg`）。
- 实际发出的请求：`provider_comfyui_video {prompt, text, aspect_ratio, resolution, duration, fps, reference_images:[2 张]}`，**没有 `mode`**。

**根因**
1. 前端把 `mode` 设上了：`client/src/components/canvas/kit/useGeneration.ts:255` 写入 `override.mode = assembled.providerMode`，值是 `'r2v'`。
2. 但执行器把它过滤掉了：`client/src/components/canvas/hooks/nodeAgentExecutor.ts:84-87` 的 `buildAgentArgs` 只放行两类 override 键：已经在 args 里的，或者在 `extraKeys` 里的。`extraKeys` 由第 204 行的 `declaredInputKeys(def)` 加上第 37–41 行的 `LEGACY_HANDLE_KEYS` 组成。comfyui_video 的 input_schema 和 params_schema 都没有 `mode`，所以 `mode` 被丢掉。
3. 后端拿不到 `mode` 就默认 i2v：`server/app/mcp/server.py:1659` 写的是 `mode=arguments.get("mode") or "i2v"`。
4. i2v 必须有首帧：`server/app/providers/video/comfyui_video.py:100-101` 在没有首帧时直接报错。

**验证**
- 用同样的参数，只补上 `"mode":"r2v"`，直接调 `/mcp/call`：成功返回 `mock_ea5ec4b2.mp4`（文件已删）。
- 结论：只要补上 mode 就能成功，问题就出在 mode 被丢掉。

**影响**
- 所有生成源在多参考模式（自动或手动）下都会被当成 i2v 下发；没有首帧时就失败或行为不对。
- 单图和首尾帧模式之所以正常，只是因为它们本来就该是 i2v，和后端默认值碰巧一致。

**建议修法**（二选一，最好两处都改）
- 前端：`buildAgentArgs` 对视频节点始终放行 `override.mode`，例如把 `'mode'` 加进 `LEGACY_HANDLE_KEYS.video`，或者在 `allowed` 里加上它。
- 后端：`server.py` 的 provider 视频分支在没有 `mode` 时按入参推断：有首帧用 i2v，有参考图或参考视频用 r2v，否则 t2v。规则和 `nodeAgentExecutor.ts:232` 的 HTTP 降级分支一致。

**B8 其余检查都通过**
- **自动匹配**：comfyui_video 和 AutoDL v2 都声明了参考图槽，两图都自动成「多参考」。`b8-02`、`b8-04`
- **参数随生成源变化**：
  - comfyui_video：比例、分辨率 480/720/1080p、时长、fps；
  - AutoDL v2：分辨率 480p竖/768p竖…、时长、seed，并提示「未声明比例参数」。
  - 切模式只改变图片的去向，不改参数（与 N3 的说明一致）。
- **手动切「首尾帧」**（AutoDL v2）：参考卡片显示 1 = 首帧、2 = 尾帧。我在浏览器里用 `page.route` 拦下 `/mcp/call` 看入参，**请求没有到达后端，没有调用付费源**：`first_frame` = 当前帧、`last_frame` = 首帧，对位正确。`b8-05`、`b8-06`
- **切回 comfyui_video**：模式下拉里标出「首尾帧（当前生成源不支持）」，面板告警「生成源不支持尾帧，参考 2 未使用」。`b8-07`
- **生成后可播放**：改用「单图参考」生成，comfyui_video 走兜底，0.37s 出片 `mock_74a8f2c8.mp4`（832×1216，5s）。节点内 `<video>` 的 readyState 为 4，播放 1.2s 后 currentTime = 1.2。`b8-09`
- **没法实测的分支**：「生成源只支持首尾帧时自动成首尾帧」。8001 上能选的 3 个视频源，要么有参考图槽，要么只收文本，没有「只有首尾帧」的源。这一支只有 N3 的单测覆盖。

### B1：扩写结果不是流式写入

**现象**
- 扩写请求发出后，卡片一直显示「生成中…」。
- 返回后正文一次性从 46 字符跳到 462 字符。我每 300ms 采样一次，中间没有任何增量。

**根因**
- 前端：`client/src/components/canvas/host/executeRouter.ts:121-129` 先 `await apiService.expandPrompt()` 拿到完整结果，再用一次 `updateNodeData` 整段写回。
- 请求本身不是流式：`client/src/services/api.ts:369` 的 `POST /llm/expand` 返回 JSON，后端 `server/app/api/routes.py:1186` 也没有流式接口。
- `nodes2/text/TextNode.tsx:9` 的注释写明了「非流式，整段替换」，是 N1 的有意取舍，但和 design §6.1（文本节点 Toonflow 部分「流式生成」）以及 testing B1 不一致。

**建议**（由协调人定）
- 一种做法：后端加 SSE 流式接口。`llm_service` 内部已经在流式调用（报错文案就是「大模型流式响应超时」），节点按 delta 节流追加到 `text`/`prompt`。
- 另一种做法：如果接受非流式，就修订 design 和 testing.md 的这条断言。

**其余部分通过**
- 原文模式输入标题、加粗、斜体、列表、表格、引用后，切到预览渲染正确，卡片预览一致。`b1-04`、`b1-05`
- 第一次扩写失败：等了 120 秒，报「大模型流式响应超时（总时限 120s）」，卡片红色错误提示正常（`b1-10`）。这是网关当时太慢（同一时段直接 curl `/llm/generate` 要 107s、`/llm/expand` 要 132s），属于环境问题。
- 重试时网关恢复，12s 成功，结果写回 `text` + `prompt`。`b1-12`

## 逐条细节

### B1 文本节点
- **步骤**
  1. 工作台「节点 → 文本」，新建节点。
  2. 点「编辑」，切到「原文」，输入 Markdown，切到「预览」，关闭弹窗。
  3. 技能下拉选「扩写」（列出 自由生成 / 扩写 / 剧本拆解 / 策划案），指令留空（按设计用正文），点发送。
- **结果**：预览的 HTML 包含 h1、strong、em、ul、table、blockquote。扩写请求是 `POST /llm/expand {prompt: 正文, kind:'image'}`，结果非流式，详见上节。
- **截图**：`b1-01`～`b1-12`

### B2 文本节点 → 图片生成
- **步骤**：两个文本节点的 `prompt` 口连到图片生成的 `in`；选中图片生成节点；在提示词里用 `@` 菜单插入参考 1，再手打 `{{ref 2}}`；然后把参考 2 拖到参考 1 前面。
- **结果**
  - 参考列表显示 2 条。用 `@` 插入的参考立刻显示为引用标签。
  - 手打的 `{{ref 2}}` 在输入时保持纯文本，重新选中节点（面板重新挂载）后才渲染成标签。
  - 拖拽后列表顺序互换，提示词里的标签编号随之互换。
  - `data.prompt` 从 `…参考 {{ref 1}}，再参考 {{ref 2}}…` 变成 `…{{ref 2}}…{{ref 1}}…`，`refOrder` 记录了新顺序。
- **截图**：`b2-05-panel`、`b2-07-ref-tags`、`b2-08-remount`、`b2-09-reordered`

- **下载**：链接地址 `http://127.0.0.1:8001/storage/assets/…/original.png`，带 `download="original.png"`。dev 下是跨域，浏览器忽略 download 属性，在新标签打开图片（见观察 2）。
- **宫格切分**：选 2×2，调 `POST /media/ops/grid-split {rows:2, cols:2}`。生成 4 个节点「图片 · 1-1 / 1-2 / 2-1 / 2-2」，位置为锚点右侧，排成 2×2（列距 238，行距 320）。

### B4 标记 + 局部重绘
- **标记**：画笔 + 矩形，点保存，调 `compose-mask`。新建「图片 - 标记」节点，并从原图的 `image` 口连到它的 `in`。toast 提示「已生成标记图片节点」。
- **局部重绘**
  1. 涂抹一块区域，填写「把涂抹区域改成一轮金色的月亮」，生成源选「ComfyUI (本地/云端)」，发送。

### B5 图片生成
- **直接生成**：智能规划关闭，选 ComfyUI，9:16、480p，发送。MCP 入参是组装后的提示词（参考 1/2 的文本按 R6 拼在后面）加 `aspect_ratio 9:16 / resolution 480p / steps 20 / cfg 7`。56s 出图，832×1216，`aspect_ratio` 保持 `9:16`，像素比写在 `result_aspect`。`b5-04`
- **智能规划**：打开开关后发送，走 `POST /canvas/agent/generate`，生成完成。面板头部显示「智能规划 · ComfyUI (本地/云端) · aspect_ratio=9:16，resolution=480p… · 规则降级」，悬浮提示里有规划理由和润色后的提示词。`b5-07`
- **附注**：两次都是 `plan_source: rule`。后端日志 21:01:28 和 21:20:10 各有一条「[AgentPlanner] LLM plan failed（预算 30s…）」。原因是 `server/app/canvas/agent_plan.py:15` 的 `LLM_PLAN_BUDGET_S = 30`，而这个网关上规划请求（大段系统提示，max_tokens 1200）30 秒内回不来。第二次重试时文本扩写只要 12s，规划仍然超时。所以 UI 链路正确，但「LLM 规划出的源和参数」这条路径在本环境没有实际跑通。如需验证，要换更快的模型或临时调大预算。

1. **B5 智能规划的 30 秒预算**：在当前网关上必定降级，见 B5 附注（`server/app/canvas/agent_plan.py:15`）。
2. **下载按钮在 dev 下不触发下载**：`kit/FloatingToolbar.tsx:86-95` 用的是 `<a href download target=_blank>`，5180 → 8001 跨域时浏览器忽略 download，改为新标签打开。生产同源部署时正常，Toonflow 也是同样写法。如果要 dev 下也能下载，可以改成 fetch 后转 blob 再下载。
3. **全局「AI 润色」按钮残留**：在文本弹窗的原文 textarea 里输入后关闭弹窗，`components/ui/GlobalAiPolish.tsx` 的悬浮按钮会一直留在原位置，甚至盖在全屏查看层上（`b1-05`、`b3-02`、`b5-01`）。
   - 原因：该组件只在 focusout 时隐藏，而聚焦中的 textarea 被卸载时 Chrome 不派发 blur / focusout。
   - 组件本身是既有的，由新的 TextDocumentDialog 触发。
   - 建议：检查 `activeEl.isConnected`，或者弹窗关闭前先 blur。
4. **文本技能结束时短暂闪出「不再等待」**：约 300ms。原因是 `nodes2/text/TextNode.tsx:98` 先 `setPending(false)`，而宿主写回的 `agent_state:completed` 稍后才到。不影响结果，只是闪一下。
5. **画布下拉的节点数不实时**：例如显示「默认画布（1节点）」、「画布2（0节点）」，实际已有多个节点，要切换画布后才刷新（`CreativeCanvas` 的顶部工具条）。

7. **MiniMap 盖住提示词面板**：节点靠右下时，MiniMap 叠在提示词面板上方，能挡住发送按钮（`b2-05-panel`）。
8. **3D 导演导出的新节点没有 asset_id**：导出的图片 / 视频已经入了素材库，但新建的图片、视频节点没记 `asset_id`，「添加到素材库」仍可点，可能重复入库。
9. **控制台 404**：3D 片场页加载时 `GET /api/v1/agent-profiles` 返回 404，与画布无关。
