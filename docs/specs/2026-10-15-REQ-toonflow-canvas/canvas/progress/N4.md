### 关键约定（H1 / 其他节点需要知道的）

- **台词键**：节点自身文本读 `text` 优先（与后端 `inputs.own_prompt`、kit `ownPromptOf` 一致），编辑时 `text` / `prompt` 同写；参考重排时 `useNodeReferences` 缺省就会同时改写这两个键。
- **生成入参**（`audioGenerationInputs`）：在 `assembleInputs` 结果上 ① `args.text = 组装后的台词`（`executeAgentNode.buildAgentArgs` 用 `d.text || prompt`，不覆盖的话会把带 `{{ref N}}` 的原始文本发出去）；② 有参考音频时额外 `args.ref_audio = 第一条`（`provider_*` MCP 工具只认 `ref_audio / ref_audio_path`，生成源槽位名如 `reference_audio` 它不读，后端 engine 也是这么补的）。
- **槽位**：`extractSlotsFromProvider(def)` **不传 nodeKind**，避免兜底出一个 `reference_audios` 槽——否则只声明 `text` 的源（MiniMax H3）也会被当成支持参考音频；现在会如实提示「生成源不支持参考音频，参考 N 未使用」。
- **参数**：存 `data.params`，镜像 `provider_params` 与顶层同名键（engine 执行器优先读顶层）；音色同时写 `voice_id`。智能规划开关存 `data.smart_plan`。
- **Toonflow 设置**：节点数据固定 `language / sampleRate / format`（Toonflow 词汇）；生成源声明了对应参数（`language|lang|text_lang|language_boost|locale`、`sample_rate|sampleRate|sr|audio_sample_rate`、`format|audio_format|output_format|response_format`）才显示并按源参数名下发，枚举值互相映射（zh-CN↔zh、ogg_opus↔opus…）。当前 8001 上所有音频源都没声明 → 只存数据。
- **上传**：沿用画布现有做法（CanvasResourcePickerModal：音频走素材库 `POST /assets`）。素材库只保留 mp3 / wav 扩展名（`asset/manager._attach_file` 白名单，m4a 等会被存成 `original.png`），所以其他格式先用 `/media/ops/speed` rate=1 原速转码成 m4a（data URI，≤37 MB 原文件），再以 `file_url` 登记素材库；上限 100 MB（Toonflow）。项目内（`actions.projectId`）为 project 作用域，没有项目 id 时为 global。
- **历史**：`data.history`（useGeneration 追加）；「替换音频」也追加一条，被替换的当前结果不在历史里时先补进去；「设为当前结果」只改 `audio_url`（旧数据带 `audio` 键时同步改，因为 `readOutputValue` 先读与出口同名的键）。

## kit / 协调问题（请协调人统一处理）

1. **COORDINATION 第 7 条写法有误**：`useGeneration(id, actions.update)` 不成立——`useGeneration` 的回写签名是 `(nodeId, patch)`，`actions.update` 只收 `patch`，直接传会把 nodeId 当补丁写进去（tsc 会报错）。要写成 `useGeneration(id, useCallback((_id, p) => actions.update(p), [actions]))`。
2. **R6 对音频目标的副作用**：节点自身台词非空、又连了文本参考时，组装结果是「台词\n\n参考 1：\n文本」，TTS 会把「参考 1：」念出来（后端 T5 只处理了自身为空的情况）。前端必须与后端一致，所以没改；建议后端对 `audio` 目标去掉「参考 N：」前缀或只用自身台词。
3. `RefList` 的图片缩略图（`item.thumb || item.value`）和 `FloatingToolbar` 下载链接直接用原始 URL，dev 下 `/storage/...` 相对地址指向 vite 源会 404，建议 kit 里统一 `resolveMediaUrl`（本节点自己传的 downloadUrl 已回源）。
4. `useProviderSources` 没有刷新入口（PromptPanel 有 `onSourcesOpen` 但 hook 拿不到新列表），新建 / 删除生成源后要刷新页面才看得到；建议返回 `reload()` 或订阅 `provider-list-refresh`。
5. `createNodesLocal`（宿主未接管时的回落）不避让已有节点，连续截取 / 变速的产物会叠在同一位置；H1 的 `createNodes` 建议用 Toonflow 规则（右侧 80px，与已有节点重叠时向下 +40px），演示页里有现成实现可抄。
6. `providerSkills.extractSlotsFromProvider(def, 'audio')` 在源未声明媒体槽时兜底出 `reference_audios`，会让「不支持参考音频」的源看起来支持；用于 assembleInputs 时建议都不传 nodeKind（本节点已如此）。

## H1 集成须知

- `import './nodes2/audio'`（或在 `nodes2/index.ts` 里 `export * from './audio'`）即完成两个节点注册；`__dev__` 不要导出。
- 宿主「保存到素材库」：音频产物在 `data.audio_url`（`load-audio` 同时有 `audio/url`，读法用 `readOutputValue(node,'audio','AUDIO')`）；`load-audio` 上传 / 拖入素材时已在素材库，带 `data.asset_id`，`canSaveToAssets` 可据此置灰避免重复入库。
- 截取 / 变速产物通过 `createNodes(specs, {placement:'right'})` 新建，不连线（与 Toonflow 一致，`load-audio` 没有输入口）。
- 宿主的 `onDrop`：素材库卡片 / 文件拖到 `load-audio` 节点上时由节点自己处理并阻止冒泡；拖到别处仍走宿主原逻辑。旧宿主「素材 → load-audio + audio」的 `targetHandle: 'ref_audio'` 连线需改成 `in`（迁移规则会转，但新建时最好直接写 `in`）。

## 遗留 / 说明

- 截取是单区间（后端 `/media/ops/trim` 只截一个区间）；Toonflow 的多片段剪辑 + 拼接需要后端 concat 接口，暂未做。
- 变速范围按后端 0.5–2.0（Toonflow 浏览器 ffmpeg 是 0.1–4）。
- 取消截取 / 变速只是丢弃结果，后端处理不可中断，产物会留在 `storage/generated/media_ops`（T2 已说明不自动清理）。
- 波形在浏览器完整解码后取峰值（Toonflow 同款），超长音频解码内存大；解码失败（浏览器不支持的格式）时仍可播放，波形区提示不可用。
- 参数弹层里 DynamicControl 沿用 MiniMax 原组件样式，浅色主题下输入框边框较淡（`border-white/70` 无浅色覆盖），属原组件问题。
- 「替换音频」的上传会进素材库（同 MiniMax 现有上传），音频生成节点没有记录 `asset_id`。
